## 三、DSH 插件与 Claude Code 插件

**结论：本工程【没有安装】任何 DSH Cordis 插件或 Claude Code 插件。** 这是有意为之：

| 类别 | 调研结论 | 决定 |
|---|---|---|
| **DSH Cordis 插件** | 调研两轮，npm 生态**不存在**可用于本场景的第三方插件 | 不装 |
| **Claude Code 插件** | DSH 无 `commands/`、`agents/`、`hooks/`、LSP 装载器，这些形态**用不了** | 不装 |
| **第三方 skill（纯 Markdown）** | 找到 6 个许可证为 MIT 的候选，但与本工程已有的自建 skill **功能高度重叠** | 暂不装 |
| `anthropics/skills` 的 docx/pdf/pptx/xlsx | 许可证 **Proprietary**（专有） | ⛔ **排除** |

⚠️ **安装第三方 skill 的两个硬门槛（实测/文档确认）**：
1. frontmatter **只认 `name` + `description`**（可选 `whenToUse`/`metadata`/`disable-model-invocation`/`user-invocable`）。
   Claude skill 常见的 `tools:` / `allowed-tools:` **不认** ⇒ **整个 skill 会被静默丢弃且无诊断**。
2. DSH 的 skill 发现深度**只有一层**（`<root>/<name>/SKILL.md`），**刻意不支持嵌套 `**/SKILL.md`**。
   ⇒ 把 skill 放进 `fpga_hank/team-resources/skills/` 这类子目录**会静默失效**。

> **向前兼容约定**：本工程若将来要引入第三方 skill，应保持 `.dsh/skills/` 为**唯一权威源**，
> 任何其他位置的副本都必须是**可再生的派生物**（单向 源 → 副本），禁止反向手改副本。

## 六、验证方式（本工程的验收口径）

按用户明确要求，**验收只认**：

1. **构建**：`gw_sh.exe` + `tools\gowin\build.tcl` → 必须产出 `.fs`，且引脚全部 `constrained=Y`
2. **仿真**：**ModelSim** + `sim\run.do` → 0 error，结果符合预期
3. **波形图**：`docs\waveforms\real\*.png` —— 共 6 张，**全部是 ModelSim 真窗口截图**（用 `PrintWindow(hwnd, hdc, 2)` 抓的真实窗口，不是脚本画出来的图）。
   > ⚠️ **本项目明确禁止"自己绘图"**（用户原话："不要自己绘图，可能自己骗自己"）。
   > 早先尝试过"testbench `$fwrite` → CSV → matplotlib 渲染"的路线，
   > **已废弃**，所有自绘草稿移到 `_smoke-test/matplotlib-drafts/`，不进交付物。
   > 理由：渲染图是"用我们自己的数据、我们自己的假设画的图"，
   > 一旦渲染逻辑或假设错了，图会**自证其说**；
   > 真窗口截图则是 ModelSim 自己的显示结果，**不给我们在中间做手脚的机会**。

其它手段（Python 脚本、形式验证、隔离基准实验）**只作辅助排查，不得作为验收依据**。
