# VB22B 实际通信协议（实测确认）

> 版本：v1.0（2026-10-21）
> 结论来源：真板实测（Sipeed Tang Mega 60K）+ 我司 I2C 主机 RTL，不是抄规格书。
> 固件：`_work_60k/hw_bringup/rtl/tof_read_top.v`（读距离）、`tof_scan_top.v`（总线扫描）

---

## 1. 一句话结论

**这两只 VB22B 出厂就是 I2C 从机，地址 `0x52`，UART 完全不出数据。**
之前"UART 没有任何回应"不是坏了，是**模块根本不走 UART**。

---

## 2. 已实测确认的事实

| 项 | 实测值 | 判定方式 |
|---|---|---|
| 供电 | 3.3 V，**40 mA** 平均 | 万用表串测 |
| 接口模式 | **I2C** | 总线扫描：只有 0x52 应答（bitmap `…4…` → bit74 → 0x08+74=0x52） |
| 器件 ID | 寄存器 **0x03 = 0x4A** | 读回 `T=0000804A`（bit15=ACK） |
| 距离寄存器 | **0x00 = 低字节，0x01 = 高字节（小端）** | 读数 `0x7E00`→交换后 `0x007E` = 126 mm，符合手距 |
| 单位 | **毫米** | 中位数 131 → 13 cm，与摆放一致 |
| SCL/SDA 空闲电平 | 黄 3.7 V / 绿 3.3 V | 万用表 |
| 上拉 | 需 **4.7 kΩ 到 3V3**，另串 **330 Ω** | 无上拉时 SDA 释放后上升过慢，ACK 会误判 |

> ⚠️ 规格书写的是"0x00 距离高字节 / 0x01 低字节"，**实测正好相反**。以本文为准。

> 🔴 **2026-10-23 补充（S5 整合时发现，很重要）**：上表结论只适用于**单寄存器读**。
> 写指针 0x00 后**连续读 2 字节（自动递增突发读）**时，**第一字节是高字节、第二字节才是低字节**
> ——与单寄存器读相反。证据：909 mm 在突发读里到达顺序是 `03 8D`；
> 拼装必须写 `{第一字节, 第二字节}`，写反会得到 `8D03`（36099 mm）。
> `inputs_top.v` 的 d_lo/d_hi 捕获有 off-by-one，恰好与这个顺序抵消，所以它当年读数看起来对；
> **S5 的 `hw_input_mgr.v` 已按突发读的真实顺序实现**（`dist_raw = {d_lo, d_hi}`）。

## 3. I2C 时序（已验证可用）

```
写寄存器（设定读指针）:  START, 0xA4, <reg>,  START, 0xA5, 读 N 字节, STOP
                          ↑ 0x52<<1|W              ↑ 0x52<<1|R
```

读器件 ID：
```
START  A4  03  START  A5  [ID]  NACK  STOP      -> ID = 0x4A
```

读距离：
```
START  A4  00  START  A5  [lo]ACK [hi]NACK  STOP
distance_mm = {hi, lo}
```

- 总线速率：**10 kHz 已验证**（100 kHz 待测；面包板 + 4.7k 建议先 10~50 kHz）。
- 实测单次两字节读 ≈ 4.4 ms（10 kHz），加报文后约 **14 ms 一笔 ≈ 70 Hz**。
  要 200 Hz 需把 SCL 提到 100 kHz（约 0.44 ms/笔）。

## 5. 已踩过的三个坑（写下来免得重犯）

1. **`sda_in` 不能做成独立输入端口**：它会被自动分到随机球上（当时是 IOB[95]），
   读回来永远是 1，ACK 全部误判为 NACK。必须用**真正的双向端口**（`inout` + 三态），
   综合后网表里应是 `IOBUF`。
2. **状态机不能把 START 的 `done` 当写完成**：扫描器一开始漏发了地址字节，
   结果 112 个地址全部"ACK"（`S=FFFF…`）。现在 START → WRITE(地址) → 检查 ACK → STOP 四步分明。
3. **UART 没反应不等于模块坏**：40 mA 电流 + 器件 ID 可读，说明模块一直是好的。
