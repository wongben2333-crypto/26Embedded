## 1. 速览对比

| 维度 | 安路 选题一 · HDMI 多媒体播放 | 高云 选题二 · 实时多音色电子乐器引擎 |
|---|---|---|
| **一句话** | 用 FPGA 做一个「音视频播放器」 | 用 FPGA 做一个「纯硬件合成器」 |
| **技术域** | 视频接口 + 存储带宽 + 文件系统 | 数字信号处理 + 音频合成 + 人机交互 |
| **主控器件** | EG4S20BG256（19,600 LUT / 4 PLL） | Tang Nano 20K（20,736 LUT / 48 DSP）/ Primer 25K（23,040 / 28 DSP）/ Mega 60K · 138K 可选 |
| **核心链路** | TF 卡 → BMP 解析 → SDRAM 帧缓存 → HDMI + 音频 | 交互传感器 → DDS/波表 → ADSR → 混音 → I2S → DAC |
| 入门门槛 | 中（SDRAM 控制器 + TMDS 需从零） | 中（DDS + I2S + 包络需从零） |
| **背景契合度** | **约 60%**（靠通用 FPGA 工程能力） | **约 85%**（电赛信号处理可直接复用） |
| 参考资料 | 官方样例 lab_ex_4 / lab_ex_5；大量 SDRAM+HDMI 教程（多为 Altera/Xilinx，需移植） | Sipeed 官方例程（PT8211 音频）+ 多个开源 FPGA 合成器（spinalSynth / 小脚丫电子琴 / mdsynth 等） |
| **资源余量** | 🔴 **紧** —— 19.6K LUT，多个加分项同时上会撞墙 | 🟢 **宽** —— 20K ~ 138K 可选，48+ 个 18×18 乘法器 |
| **客观量化** | 弱（评委主观综合评分） | 🟢 **强**（活跃振荡器总数 × 采样率，公式明确、可增量堆） |
| 加分项 | 5 项：字幕叠加 / 转场特效 / 图片缩放 / OSD 调参 / 音频可视化 | 4 项：复音 ≥32 / 3 维表情+效果器 / ≤5ms+可视化 / 蓝牙 App 联动 |
| **竞争密度** | 🔴 高 —— 「安全题」，扎堆报名 | 🟢 低 —— 音频题冷门，差异化明显 |
| 翻车风险 | 中（时序类问题，调通即稳） | 中高（音质/延迟偏主观 + 需自研交互传感器） |
| 演示方式 | 插 HDMI 即演示，视觉冲击强 | 现场弹奏发声 + 频谱/LED 可视化，互动性强 |
| 拿奖画像 | 二等打底；一等需把 5 项加分项做满 | 二等可期；一等路径更清晰（复音数线性可堆） |

## 2. 题目内容拆解

### 2.1 安路 · HDMI 多媒体播放系统

**基础交付（必须完成）**
- 本地图像资源**扫描**（TF/SD 卡文件枚举）
- **BMP 图像解析**（54 字节文件头 → 宽/高/位深/像素偏移）
- **SDRAM 帧缓存管理**（写入图片、按像素时钟读出）
- **HDMI 视频显示**（TMDS 编码 + 行场时序 + 5× 像素时钟）
- **HDMI 音频输出**（或走板载音频通路）
- 交互控制（按键/拨码切图、自动轮播）+ 音视频联动

**硬性约束**
- 所有算法与控制逻辑必须在 **FPGA 内自主实现**
- **不得带额外处理器**（无论辅助控制还是算法预处理）
- 可用多块同款 FPGA 板卡构建主从结构

**加分项（5 项，官方明确「完成 3 项以上且完成度高可得较高分」）**
① 图层叠加与字幕（时间戳/标语、平滑滚动）
② 图片切换与转场特效（淡入淡出、滑动）
③ 图片缩放适配（不同分辨率 → HDMI 分辨率）
④ 实时调节与信息叠加（亮度/对比度 + OSD）
⑤ 音频可视化（频谱/波形叠加到画面）

**官方样例（重要！）**
- **lab_ex_4**：TF 卡图片 → SDRAM → HDMI，按键切图 + 自动轮播
- **lab_ex_5**：640×480 24 位非压缩 BMP + HDMI 音频测试音

### 2.2 高云 · 实时多音色合成电子乐器引擎

**基础交付（必须完成）**
- **自研交互形态**，≥2 个独立可控维度（电容触摸 / 光电 / 压力 / 手势）
- 精准识别选音、和弦、触发、**拨弦**等演奏指令
- **纯 HDL 实时音频合成**（波表采样 / 加法合成 / FM / 物理建模）
- 逐样本、逐声部实时运算；**I2S → DAC** 解码发声
- **复音数 ≥4**（四路以上独立声部并发发声）
- **控制到发声总延迟 ≤10ms**
- ADSR 包络、单音实时变调、多声部实时混音

**硬性红线**
- **严禁直接播放预录 PCM / 预置推流 / 整段录音触发**——必须逐音逐样本实时生成

**加分项（4 项）**
① 复音 ≥32（或加法合成 ≥32 路 / 多条并行物理建模单元）
② ≥3 维表情控制（力度/滑音/颤音）+ ≥2 音色切换 + 硬件混响·延迟·合唱
③ 延迟 ≤5ms 且确定性无抖动 + 硬件可视化（LED 指引/李萨如/频谱/波形）
④ 脱机 LED 曲目指引 + 蓝牙 App 联动

**评分公式与现场验证**
- **评分 = 同时活跃可闻独立振荡器总数 × 实际音频输出采样率**（过采样不叠加加分）
- 独立发声单元 = 含独立相位累加器 + 频率调控 + 包络控制的完整振荡器
- 现场需在**测试模式输出多路不同频率**，频谱可观测对应数量**独立谱峰**，并用 RTL 佐证纯硬件通路

## 3. 难度分解（★ 越多越难）

| 子能力 | 安路 | 高云 |
|---|---|---|
| Verilog RTL 设计 | ★★★★☆ | ★★★★☆ |
| 时序约束与跨时钟域 | ★★★★☆ | ★★★☆☆ |
| 存储 / 带宽管理 | ★★★★☆ | ★★☆☆☆ |
| 外设 / 接口协议（TMDS·I2S·FAT / I2S·I2C·ADC） | ★★★☆☆ | ★★★☆☆ |
| **算法 / DSP** | ★★☆☆☆ | **★★★★☆** |
| 资源优化 | ★★★★☆（19.6K 很紧） | ★★★☆☆（可选大板） |
| 硬件 / 机械设计 | ★☆☆☆☆ | ★★★☆☆（自研传感器） |
| 演示与答辩 | ★★★☆☆（视觉易讲） | ★★★☆☆（要讲清「纯硬件」） |

**读法**：安路的难点在**「时序 + 带宽」**（硬工程）；高云的难点在**「DSP + 资源扩展」**（软算法）。前者是"调通就稳"，后者是"指标可堆但有硬门槛"。

## 4. 我们的优势匹配（蓝桥杯 FPGA + 电赛信号题 + 集创赛 + 单片机）

**共同底子**：蓝桥杯 FPGA → Verilog/状态机/时序；集创赛 → 模块化 RTL、仿真验证、资源意识；单片机 → SPI/I2C/UART/按键/数码管等外设驱动。

### 安路 HDMI 播放 —— 契合度约 60%
- ✅ **蓝桥杯 FPGA** → Verilog/时序基础直接可用
- ✅ **单片机基础** → TF 卡、SPI、按键消抖、数码管显示思路相通
- ✅ **集创赛** → 模块化 RTL 划分与仿真习惯
- ⚠️ 视频与 HDMI 是**全新领域**：TMDS 编码、像素时钟、SDRAM 控制器都要从零学
- ❌ **电赛信号处理经验基本用不上**（只有第 5 项加分「音频可视化」能沾边）
- **结论**：靠通用 FPGA 工程能力硬打，优势不明显

### 高云 电子乐器 —— 契合度约 85%
- ✅✅ **电赛信号题 = 本赛题的核心技能包**：DDS/相位累加器、数字滤波、包络、FFT/频谱、采样率与混叠——几乎可直接复用
- ✅ **集创赛** → 流水线设计、资源复用、时序收敛（**复音扩展本质就是资源优化题**）
- ✅ **单片机** → I2C 配置触摸芯片、I2S、ADC 力度采样、按键矩阵
- ✅ **蓝桥杯 FPGA** → Verilog 基础与仿真
- ⚠️ 新增知识是「音频合成」：ADSR、波表、混音、音色设计——但都落在熟悉的 DSP 范畴内
- **结论**：**优势高度契合，边际收益最大，是把已有技能直接变现的题**

## 5. 难点清单

### 安路 · 7 个坑
1. **SDRAM 控制器**要从零理解：初始化、刷新、突发读写、读写仲裁（官方样例可复用，但改分辨率/加功能必须懂）
2. **HDMI TMDS**：4 对差分线 + 5 倍像素时钟 + 8b/10b 编码，时序一错就是黑屏/花屏
3. **显示带宽 vs 写入带宽仲裁**：乒乓/双缓冲防撕裂，带宽算错就闪屏
4. **HDMI 音频**走 data island 打包较复杂（可用板载音频通路规避）
5. **资源撞墙**：EG4S20 只有 19,600 LUT，多个加分项同时上会放不下
6. **图片缩放插值质量**：双线性插值需乘法器 + 行缓存
7. **转场特效需双帧缓存** → SDRAM 容量与带宽压力成倍增加

### 高云 · 7 个坑
1. **复音扩展的资源瓶颈**：每路 = 相位累加器 + 波表访问 + 包络 + 乘法器 + 混音，32 路需精细规划
2. **波表 ROM 多端口访问踩坑**（社区实测）：*"这个 ROM 不会被自动综合成 EBR，如果强制综合的话，会出现复音很奇怪的情况"* —— 分布式 ROM 可并行访问，EBR 串行。解法：复制多份波表 或 时分复用
3. **多路混音溢出**：相加会溢出，必须做饱和/压缩，否则爆音
4. **≤10ms 延迟的严格流水线**：传感器采集 + 键扫描 + 合成 + I2S 全链路都要确定性延迟
5. **音色设计（谐波配比）**：需用 FFT 分析参考音色——**正好是强项**
6. **自研交互传感器**：电容触摸需 RC 充放电检测、光电需比较器/ADC——**唯一的「硬件活」**
7. **效果器**（混响/合唱）需 BRAM 延迟线 + 梳状/全通滤波器——又是信号处理

## 6. 学习路径

### 安路 · 从官方样例切入最快

| 阶段 | 内容 |
|---|---|
| **1｜环境与样例（2–3 天）** | 安路 TD 软件 + License + 下载器驱动；**直接跑通 lab_ex_4 / lab_ex_5**（最快起步，能立刻看到画面、听到声音）；读板卡原理图（HDMI/SDRAM/TF 卡引脚、时钟源） |
| **2｜基础理论（约 1 周）** | HDMI/DVI 原理（TMDS 编码、行场时序、5× 像素时钟）；SDRAM 原理（行列地址、Bank、刷新、突发）；BMP 格式（54 字节头、自底向上排列、24 位对齐）；FAT 文件系统基础（或裸扇区读取） |
| **3｜模块级实现（1–2 周）** | 显示通路：彩条 → 纯色 → 单张图片；存储通路：写图片 → 读图片 → 乒乓缓冲；交互通路：按键消抖 → 切图 → 自动轮播 |
| **4｜加分项（约 2 周）** | 转场特效 / 图片缩放 / OSD 字幕 / 音频可视化 |

### 高云 · 先「让板子出声」再谈复音

| 阶段 | 内容 |
|---|---|
| **1｜环境与出声（2–3 天）** | Gowin IDE 安装（**25K 需 V1.9.9Beta-4 或更新**）；**跑通 Sipeed 官方 PT8211 (Stereo Audio) 例程**——先让板子出声；认清板载音频通路（Nano 20K 板载 MAX98357A 功放；Primer 20K Dock 有 PT8211 DAC + 3.5mm 耳机口，自带 I2S 通路，省一大块硬件） |
| **2｜音频理论（约 1 周）** | DDS 原理（相位累加器、频率字、采样率与奈奎斯特）；波表合成 / 加法合成 / FM / 物理建模的区别与音色特征；ADSR 包络（四段）；I2S 时序（BCLK/LRCLK/SDATA）与 DAC 接口 |
| **3｜单音 → 复音（1–2 周）** | 单音 DDS + 用频谱验证音高正确；加 ADSR → 多音色 → 4 路复音 + 混音；扩展 16/32 路，做资源优化（时分复用 / 波表复制） |
| **4｜交互 + 加分项（约 2 周）** | 自研传感器（≥2 维）+ 力度 + 效果器 + 可视化 |

## 8. 选型结论

| 你们的目标 | 选它 | 理由 |
|---|---|---|
| **想要最稳** | **安路** | 官方样例托底，W1 就出画面，二等打底；代价是创新性弱、报名扎堆、19.6K LUT 容易撞墙。适合"全队只想写 Verilog、不想碰硬件" |
| **想要更高上限** | **高云** | 背景契合 85%、竞争密度低、**评分公式客观可增量堆**（复音 4→8→16→32 是一条线性可控的加分曲线）；代价是需自研交互传感器、音质与延迟要求硬 |
| **冲一等奖** | **高云** | 复音数可量化堆叠且有客观公式；安路要靠 5 项**主观**加分项去博 |
| **稳拿国奖不翻车** | **安路** | 时序类问题调通即稳，现场插 HDMI 即演示，几乎没有现场翻车风险 |

> ### 最终建议
> 以「电赛信号题」的背景，**高云电子乐器的边际收益更大**——DDS、滤波、包络、FFT 频谱全是已有技能，等于把已有能力直接变现。
> **前提**：团队里至少有 1 人愿意花约 1 周搞定"≥2 维自研交互"（最简做法：光电对管阵列 或 电容触摸按键 + 一个 ADC 力度通道）。
> **若做不到这一点，就选安路 HDMI 播放**，用官方样例保底，把 5 项加分项做满去争二等/一等。
