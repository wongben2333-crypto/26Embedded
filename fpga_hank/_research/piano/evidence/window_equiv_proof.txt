# 两拍清零窗口：穷举全部 512 个 note-on 相位的等价性证明（2026-10-06, piano-tone）

## 目的
两拍清零窗口唯一的风险是「优先级写错 ⇒ 某个 note-on 相位上样本值变了」。
note-on 相对 `sample_tick` 的相位有 512 种 ⇒ **512 种全跑**，每种 dump 前 16 个输出样本，
再与「窗口关闭」的**同一份 RTL** 逐字节比对。

## 变体构造（唯一一处改动，其余字节完全相同）
```
线上（有窗口）: if (on_pulse_d)
变体（无窗口）: if (1'b0 && on_pulse_d)
```
⇒ 比较的是「同一份 RTL 的有/无窗口」，不是「像不像」。

## 结果
| | sha256 |
|---|---|
| 有窗口 | `29D5E7FE66AB003270475A98F984F566E3D68C3E188B56D66D0BCF8301AFE016` |
| 无窗口 | `29D5E7FE66AB003270475A98F984F566E3D68C3E188B56D66D0BCF8301AFE016` |

**PASS —— 完全一致。该补丁对【全部 512 个 note-on 相位】不改变任何样本。**

覆盖范围：**512 相位 × 16 样本 = 8192 个输出样本**（原始数据见 `phase_dump_window_on.txt`）。

## 旁证（同一版本的其它验证）
- 常规逐样本回归：**7 个文件 sha256 全同**（表情输入全 0 vs 加表情之前）
- 相位扫描 TB：**64 / 64**
- 延迟分布：min 516 / P50 772 / P95 1001 / P99 1021 / max 1027 clk —— **与打补丁前完全相同**
- flow-verifier 独立 TB：A5/A4 = 2.000122、C4/A4 = 0.594596

## ⚠️ 边界（不许夸大）
仿真里逻辑是**零延迟**的，所以「CE 晚建立一拍仍能清零」**无法在仿真中直接演示**。
仿真能证明的是【补丁不改变行为】；收益是**结构性的**：`ph` 的清零 CE 多了一拍窗口
（见 `piano_engine.v` 中 `if (on_pulse_d) ... ph[j] <= 0` 位于 always 块最前面 = 最低优先级）。
