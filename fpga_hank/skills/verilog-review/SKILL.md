# RTL 审查清单（按"最常出错"排序）

按顺序走一遍。每一条都给出**如何发现**与**典型症状**——本项目实际踩过的坑都在里面。

## 1. 同一寄存器被多次赋值（最高频、最难查）

**症状**：寄存器卡死在某个值，或"每拍只前进半格"直至停滞。波形上表现为"设计不动了"，
看着像复位没放开。

**发现**：对每个寄存器，数它在同一个 `always` 块里出现多少次 `<=`。

```verilog
// ❌ 错误：两个并列 if 分支都可能给 ph 赋值，条件重叠时"最后一次生效"
if (tick) begin
    if (ph == 4'd15) ph <= 4'd0;
    else             ph <= ph + 4'd1;
end
if (tick) ph <= ph_next;      // ← 这行会覆盖上面，且构成延迟链

// ✅ 正确：一个寄存器只有一条赋值路径
if (tick) ph <= (ph == 4'd15) ? 4'd0 : ph + 4'd1;
```

**本项目实例**：`pt8211_tx.v` 曾有 `new_ph <= ph+1` + 末尾无条件 `ph <= new_ph`，
因为后者每拍执行而前者只在 tick 更新，构成串行延迟链，`ph` 每个 tick 只前进半格。
**教训：不要为了"可读性"引入影子寄存器。**

## 2. 组合反馈 / 组合环

**症状**：综合报 combinational loop，或仿真出现振荡。

**发现**：检查 `wire` 是否被它自身间接驱动。用 `assign` 连成的链里若回到起点即为环。

## 3. 不完整条件导致 latch

**症状**：综合报告出现 `Latch inferred`；上板后行为随温度/布局漂移。

**发现**：`always @(*)` 块里每个输出在所有分支都必须有赋值，或给默认值：

```verilog
always @(*) begin
    y = 1'b0;            // ← 默认值，消除 latch
    case (sel) ... endcase
end
```

注意：**时序块 `always @(posedge clk)` 里不完整赋值不会产生 latch**（会保持原值），
这是常见误解。latch 只来自组合块。

## 4. 位宽陷阱（Verilog 的隐式截断）

| 陷阱 | 说明 |
|---|---|
| `32'd1 << 32` | **等于 0**（左操作数是 32 位）。`FRAC_BITS ≥ 32` 时分频小数补偿直接失效 |
| `a + b` 赋值给更窄的 reg | 高位被静默丢弃，进位丢失 |
| `{a, b}` 拼接总宽不匹配 | 左侧被截断或补零 |
| 有符号/无符号混算 | 整个表达式变为无符号，负值变巨大正数 |
| `a[15 - idx]` 其中 `idx` 位宽不足 | 索引回绕，取到错误的位 |

**本项目实例**：`pt8211_tx.v` 用 `FRAC_BITS=32` 时 `32'd1 << 32 == 0`，
导致 `frac_carry` 恒为真，分频比完全错。

## 5. 动态位选产生 x

**症状**：某一路输出恒为 `x`，但其它路正常。

**原因**：`reg[15:0] r; r[15 - idx]` 若 `idx` 可能超出范围，或表达式被综合器
判定为不可静态分析，结果可能是 `x`。

**对策**：把左右/各路**分开写成独立分支**，不要用三元表达式混合：

```verilog
// ❌ 曾导致右声道 din 恒为 x
din <= (is_right) ? sample_r[15 - idx] : sample_l[15 - idx];

// ✅ 分开写，静态可分析
if (is_right) din <= sh_r[15];
else          din <= sh_l[15];
```

## 6. 跨时钟域（CDC）

- 单比特控制信号：**两级同步器**（2FF）。
- 多比特数据：不能只打两拍 —— 用握手、异步 FIFO，或格雷码。
- **不要用分频出来的时钟驱动逻辑**。工具会替分频时钟编造频率，
  产生未约束的 CDC，偶发漏采样。
  **本项目实例**：PT8211 驱动曾用分频位时钟跑逻辑，结果"音不准"而非"咔哒声"，
  极难定位。现在整个音频通路只有一个时钟域。

## 7. 复位

- 明确选同步还是异步，全设计统一。
- **不要在异步复位下推断 BSRAM**：Gowin 的 BSRAM 是严格同步器件，
  带异步复位的读逻辑会导致 BRAM 推断失败（掉到分布式 RAM，资源暴涨）。
- 复位释放要同步（避免亚稳态）。

## 8. 综合推断核对（Gowin 特有）

综合报告里的资源占用**是唯一可靠证据**。若某项为 0 而设计显然用了它，说明推断失败：

| 想推断 | 检查报告里的 | 常见失败原因 |
|---|---|---|
| BSRAM | `BSRAM` 数量 | 异步复位、异步读、位宽/深度不匹配 |
| DSP 乘法器 | `DSP` 数量 | 有符号/无符号混算、常数乘法被优化成移位 |
| 移位寄存器 | `SSRAM` | 带异步复位 |
| ROM | `ROM16` / BSRAM | 初值未给 |

读法：`eda_proj/<name>/impl/pnr/<name>.rpt.txt` 的 `3. Resource Usage Summary`。

**本项目实例**：冒烟测试的计数灯设计占 `69/138240 LUT`、`48/139095 Register`，
与设计规模相符即正常。

## 9. 多驱动与三态

- 同一 `wire` 被多个 `assign` 或模块端口驱动 → 综合报多驱动。
- FPGA **内部**不要用三态，只在 IO 上用 `inout` + `IOBUF`。
- 注意 `IO_LOC` 里同一引脚被约束两次。

## 10. 命名与可审查性（赛题会对着代码数振荡器）

评委要能"一眼数出振荡器实例"。因此：

- `generate` 出来的振荡器数组要**参数化且实例化清晰**，不要藏在复杂的条件生成里。
- 每个振荡器实例要有：**独立相位累加器 + 频率字 + 包络**，三者在一处可见。
- 顶层信号/寄存器**小写**，参数/常量**大写**（高云官方编码建议）。
- 禁止出现音频样本 ROM、SD 卡读 WAV 的代码路径（赛题红线）。

## 11. 时序约束

- 每个时钟都要有 `create_clock`，否则 `run pnr` 报
  `WARN (TA1132): 'clk' was determined to be a clock but was not created`。
- 慢速输出（LED、DAC 串行线）用 `set_false_path`。
- Gowin 的 SDC 解析器**不接受反斜杠续行**，每条约束写一行。

## 12. ★ 先找参考实现，别自己试错（最重要的一条工作方法）

这是纯粹的时间浪费。** 遇到仿真/综合问题时的正确顺序：

1. **先搜 GitHub 上同类开源项目**，找**同芯片/同板卡**的最相关
   （本项目：`vdalex/tangmega-138k-fpga-projects`，Tang Mega 138K 实机工程，
   含 `fractal_music/tools/music_model.py` —— 29 KB 的 **Python 权威模型**）。
2. **读它的 Python/行为模型**（如果有）。硬件模型比读 RTL 更快更准，
   而且注释里往往直接记录了"为什么这样写"和踩过的坑。
3. **只借鉴设计决策，不要抄代码**（许可证 + 赛题要求自研）。

### 已验证的权威设计要点（来自参考模型的声部循环）

```python
if env[v]:                                  # ★ 只推进"活着"的声部 → 相位冻结
    phase[v] = (phase[v] + inc[v]) & 0xFFFFFFFF
    s = wave[tbl[v]][phase[v] >> (PHASE_BITS - WAVE_BITS)]
    a = (s * env[v]) >> 16                  # ★ 波形 × 包络，全宽乘积再移位
    acc_l += (a * (255 - pan[v])) >> 8      # 声像
    acc_r += (a * pan[v]) >> 8
    env[v] -= (env[v] >> DECAY_SH) + 1      # ★ 指数衰减包络（不是线性 ADSR）
dry_l = acc_l >> MIX_SH                     # ★ 混音缩放
```

三条可直接套用的结论：

| 结论 | 说明 |
|---|---|
| **静音声部必须冻结相位** | 不是优化，是音乐正确性。每次归零会让和弦叠加方式与预期不符（听感是"和声不对"）。而且不是边角情况：包络归零后声部会静音很久才被重新触发 |
| **包络用"指数衰减"实现** | `env -= (env>>DECAY_SH)+1` 每采样递减。这比线性 ADSR 更贴近真实乐器；线性 ADSR 适合演示"看得清"的场景（本项目 `adsr.v` 两种都提供） |
| **混音必须先缩放** | `(s*env)>>16` 后再累加，最后 `>>MIX_SH`。乘积必须在**全宽网络**上形成再移位，否则被截断成噪声（参考实现明确记录"听起来就完全是噪声"） |

### 工具链行为（参考实现踩过、我也复现过）

| 行为 | 后果与对策 |
|---|---|
| 每声部数组**只能有一个写语句** | 从两处写会被推断成双口 block RAM，然后报一个关于 DPB 写模式的莫名错误。索引与数据都要在那一个语句里 MUX |
| 小数组会被推断成 RAM16 | 行为与触发器一致（RAM16 异步读），**不要对抗**。`(* ram_style = "registers" *)` 和 `(* syn_ramstyle = "registers" *)` **都无效**（参考实现试过并记录） |
| 顶层**悬空输出**会让整个模块被 sweep | 实测：Gowin 报 `WARN (NL0002): module "X" ... is swept in optimizing`，于是该模块的输入变成常量/悬空，功能静默消失。**顶层不要留悬空端口** |
| 常量折叠会让有意的模块"看起来被删除" | 若模块输出是编译期常量，工具会内联并折叠。判断依据不是"模块名是否在网表里"，而是**资源数是否合理**（本项目靠 FF 数 1414 确认包络仍在实现） |
| ROM 用 `initial $readmemh(...)` + `(* ram_style = "block" *)` | 比手写 case/LUT 更省、更清晰。Gowin 对某些大 `case` ROM 会**跳过初始化**导致 ROM 全空（参考实现记录过） |
