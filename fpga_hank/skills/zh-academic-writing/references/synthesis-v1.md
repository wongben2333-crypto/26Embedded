## 一、三条边界（**最高优先级，优先于所有规则**）

| 边界 | 要求 |
|---|---|
| **信息守恒** | 事实、数字、公式、符号、引用、术语、限定词、否定、条件、归因，**一个不增一个不减**。不补例子、不补数字、不替作者编经历或论断。原文缺证据 ⇒ 标"待确认"，**不自己填** |
| **语体不降级** | 正式平实的现代书面语。**不加**"说白了""讲真""我觉得"，不加感叹号，不写反问。技术文字里，**中性和克制本身就是人的声音** |
| **不造新口癖** | 同一替换词**一页出现三次以上**就换一种改法。**原稿没有的标点习惯，改稿也不引入** |

**⇒ 规则打架时选改动更小的那条；拿不准是否命中规则，就不改。**

## 二、改稿顺序（**六层漏斗，顺序不能颠倒**）

> 来源：eloquent-science 的漏斗 + tuiqiao 的五遍

```
1. 文档     整体故事线对不对？章节顺序对不对？篇幅对不对？
2. 章节     每章各司其职？节尾给的是判断而不是缩写？
3. 段落     一段一个主旨？段首主题句？与前后衔接？
4. 句子     主动？直接？长短交替？主谓距离短？
5. 词语     动词承重？删空洞短语？术语精确？
6. 细节     标点、中英混排、数字与单位、图表编号、引用
```

**⇒ 结构不稳，绝不打磨字句。在一个本不该存在的段落里修句子是白费力气。**

## 三、⭐⭐ 本项目专属的体裁基准（**从三份往届参考逆推，最重要**）

### 3.1 人称与叙述位置
| 用 | 不用 |
|---|---|
| **本系统 / 本设计 / 本作品 / 项目** | ⛔ **我们** |
| 客观陈述（"系统采用…"、"该模块负责…"）| ⛔ 心理活动（"我们最初以为…"）|
| 数据说话 | ⛔ 失败叙事（"第一次失败了，第二次更差"）|

**⇒ 教训/反思类内容只允许出现在「心得体会」一节，且要具体到事、客观表述。**

### 3.2 评分相关内容的位置（**本项目特有约束**）
```
⛔ 全文任何位置不得出现"评分/分数/拓展①/红线"等字眼
✅ 只允许在【完成情况】一节集中交代"哪些做到了、哪些没做到"
⇒ 正文前半读起来应是一份纯粹的"我们做了个什么东西、怎么做的"技术文档
```

### 3.3 五个固定句式（照参考文档）
```
设计目的   ：为了/面向 <要解决的问题> …… 本设计旨在开发 <什么系统>，主要目的如下：
             （N）<短语>：<一句话>；
应用领域   ：<一句引导语>：
             （N）<领域名>：<使用者>可以<做什么>；
技术特点   ：本系统的主要技术特点有：
             （N）<特点名>：<基于/采用什么>，<实现了什么>，<量化收益>；
性能指标   ：本系统的关键性能指标如下：
             <指标名>：<在什么条件下>达到 <数值>。
创新点     ：（N）<名称>：<做了什么，用了什么手段>。<因此带来的好处>。
```

### 3.4 五条的硬约束
| # | 约束 |
|---|---|
| **1** | 每条 **1–2 句**；**原理细节留给正文各模块章**，不进 1.2/1.3 |
| **2** | **指标不提前出现**；1.2/1.3 不写具体数值，数值只放 1.4 与测试章 |
| **3** | **数字必须带条件**（时钟频率、测试集、样本数、测试环境），否则无意义 |
| **4** | **弱指标照写**：往届国一把 `FPGA 实测 72% vs 仿真 97.53%` 并列 ⇒ 未达标项如实写 |
| **5** | **指标只呈现数据，不写"依据哪份报告/哪个构建/怎么得出"** ⇒ 依据放章末"本章数据来源" |

### 3.5 图表公式排版（**照实测规格**）
| 项 | 规格 |
|---|---|
| **图号** | 章-序，`图 2.1`（不是"图 2-1"，不是全局连续）|
| **图题** | **黑体 10.5pt，在图下**，格式 `图N 空格 说明` |
| **表题** | **黑体 10.5pt，在表上** |
| **公式** | ⭐ **居中 + 右顶格 `(N)` 全局连续编号**（Word 用 CENTER 7.9cm + RIGHT 15.8cm 双制表位）|
| **公式符号** | 指数统一 `2^n`（**不要同篇混用 `2^W` 与 `2¹⁷`**）；减号统一 `−`；`⇒` 用 `⟹`；赋值不用 `←` |
| **每张图** | 必须被正文引用，并说明"从图里看出了什么" |
| **待补图** | 用统一占位图 + 引用块写明"需要什么、建议怎么取" |

## 四、⭐⭐ 深度写作六问（**每个关键技术点都要答**）

> 来源：technical-proposal-expert。**用来治"泛泛而谈"** —— 只有概念词（加法合成、多音色、低延迟）而没有选型理由、机制细节、指标支撑，是最大的质量问题。

| # | 问 | 本项目的答法示例 |
|---|---|---|
| **1** | **解决什么问题** | 弓弦是能量持续输入、稳幅振荡，拨弦式包络听起来像"拨"的二胡 |
| **2** | **为什么这么选** | 定速斜坡而非"再选一个移位量"：后者会多出一个 32 位变量移位器（≈160 LUT × 6 泛音 × 8 声部 ≈ 7 700 LUT）|
| **3** | **关键机制与数据流** | `env ← env − (env>>s) + drive`，稳态 `env* = drive × 2^s` |
| **4** | **工程化落地** | 只用常量移位与比较器；128 档线性驱动量；仅对二胡生效 |
| **5** | **如何验证** | 钢琴/吉他输出逐值比对不变；软削波触发率 11.70%→0.77% |
| **6** | **风险与降级** | 驱动量若按整数叠加，最小非零值即饱和 ⇒ 弓速退化成两态控件 |

**⇒ 六问缺一即为"浅"；答案里出现"先进""高效""强大"等修饰词而不含数字，即为"虚"。**

## 五、⭐ 口癖清单（**逐个查，但成片的才改**）

### 5.1 强信号（**见到就查上下文**）
| 类 | 表现 | 改法 |
|---|---|---|
| **句首评论语** | 「值得注意的是」「需要说明的是」「值得一提的是」 | 删（或只补一个回指词）|
| **翻案腔** | 「不是 A，而是 B」「与其说」「说到底」 | 平说。**⚠️ 若是在纠正读者真会有的误解，保护清单要求保留** |
| **复述式推论** | 「这意味着」「换言之」后句与前句**同义** | 删后句 |
| **金句/升华** | 「价值在于…」「意义在于…」「奠定了…」「具有重要的…」 | **还原成陈述句** |
| **越证据断言** | 「证明了」「彻底」「完美」「充分说明」 | 降级为「表明」「在本配置下」 |
| **元话语** | 「接下来」「下面将介绍」「综上所述」「如上所述」 | 删 |
| **空转领句** | 「主要包括以下几点：」「主要有以下三方面：」 | 直接写内容 |
| **话题壳** | 「对于……来说」「从……的角度看」「在……方面」 | 删 |
| **概括盖掉具体** | 同段已有数字却写「显著提升」 | 用数字 |
| **黑话/工程腔** | 「收口」「兜底」「落盘」「拉满」 | 换白话 |
| **拟人化喻体** | 「像一位永不疲倦的助手」 | 删 |
| **模糊归因** | 「研究表明」而无引用 | 给引用或删 |

### 5.2 成片才改的（**不要见一个改一个**）
「可以」虚化、限定词叠用、顿号长串、引号造词、装饰性加粗、**分号连用**、短主语后单独加逗号

### 5.3 ⛔ 已被推翻、**不能据此改**的
句长不够参差、同一名词反复出现、被动和名词化本身、三项并列、问句和比喻本身

### 5.4 ⭐ 保护清单（**看着像毛病、其实该留 —— 最常误伤**）
```
下定义的「即」「称为」与术语首现加粗
同一术语一名到底（为避重复换词，读者会以为换了东西）
证据性限定（通常、可能、几乎、据……报告）
决定真假的「之一」、限制性定语、量词「存在」、计数和引入新对象的「一个」、消歧的「被」、实验条件「在……上」
已成术语的「性」「化」「度」
推理里的「因此」「所以」
真实顺序里的「首先」「第一」
纠正读者真会有的误解的「不是 A，而是 B」
带来新推论的「这意味着」
分号的正当用法（① 内部有逗号的并列分句 ② 冒号后的分项列举）
交代证据来源的主语和动词
段首加粗小标题、章首导读、章末小结、交叉引用
被动、名词化、长句、句内真排比、问句、比喻本身
引用的原文、代码、提示词一律照录
```

## 六、用词与句法（**W 系列**）

| 编号 | 规则 | 例 |
|---|---|---|
| **W1** | 万能动词 + 抽象名词 **还原成动词** | 「进行重排序」→「重排」；「实现了提升」→「提升了」；「进行了比较」→「比较了」 |
| **W2** | 「对应」「具有」「存在」「扮演…角色」换成**真实关系** | 「一一对应」要数两边项数 |
| **W4** | 「被」默认去掉；「被称为」→「称为」 | |
| **W5/W7** | 删话题壳 | 「对于……来说」「从……角度看」 |
| **W6** | 「通过……使」会**吞掉主语** | 改「……使……」或点明主语 |
| **W8** | 句首「作为 X」的 X **必须就是主语** | |
| **W9** | 长前置定语**拆成后置小句** | |
| **W10** | 「这一 + 名词」→「这个」「这种」 | |
| **W11** | 不计数、不引入新对象的「一个」**删掉** | |
| **W12** | 硬造的「性」「化」「度」**改回形容词** | |
| **W16** | 「正是」「恰恰」「格外」「尤其」**先删掉念一遍** | |
| **W17** | 「便」「之」「其」「此」成堆时换白话 | |

**⇒ 删空洞短语**（eloquent-science 对照表）：
「以便于……的目的」→「为了」｜「由于……这一事实」→「因为」｜「在……的邻近区域内」→「在……附近」｜「对两个模式的差异进行了考察和讨论」→ 写出**具体的发现**

## 七、标点（**PN 系列，依据 GB/T 15834—2011**）

| 规则 | 要求 |
|---|---|
| **破折号** | 只用于正文里的**解释说明**，**不制造揭晓式停顿** |
| **冒号** | 只用在有停顿处，**一句之内不套用两个** |
| **分号** | 只用于 ① 内部有逗号的并列分句 ② 冒号后的分项列举 ③（GB/T 允许）非并列多重复句第一层——**技术文里多半拆成两句更清楚** |
| ⭐ **经验阈值** | **全文每千汉字超过一个分号，就逐个查用途**（本项目实测曾达 **6.76** ⇒ 必须处理）|
| **PN16** | ⭐ **短主语后面不单独加逗号**（「缓存，是用空间换时间的办法」✗）|
| **引号** | 不为强调而加 |
| **中英混排** | 中文与英文、数字之间**加空格** |

## 八、行文（**F 系列**）

| 编号 | 规则 |
|---|---|
| **F1/F5** | 开头**直接进入事实或有代价的问题**，不用「随着……的发展」铺垫；新概念**先例子，再定义，再形式化** |
| **F2** | 旧信息在句首，新信息在句尾；前一句结尾接成后一句开头 |
| **F3** | 一段之内**主语尽量不换** |
| **F4** | 一段一个议题，**要点落在前两句**；最佳 4–8 句，避免单句成段 |
| **F7** | ⭐ **枚举写进句子**，不预告「有三个观察」再排「第一、第二、第三」 |
| **F9** | 段间靠**复述上段末尾名词**、一个真问题、一个总括指代来衔接；**删「接下来我们将介绍」式元话语** |
| **F10** | ⭐ 节尾**给判断**（边界、代价、反直觉推论、留给下一节的问题），**不把各段挨个缩写一遍，不升华** |
| **F11** | 章节回指用括号，**紧跟它支撑的说法** |

## 九、文采（**T 系列 —— 放在最后改，且克制**）

技术文章的文采是**精确和经济**，不是辞藻。

| 编号 | 做法 |
|---|---|
| **T1** | 让**动词承重** |
| **T2** | 往准里炼字：「影响」→ 真正发生的「拖慢」「掩盖」 |
| **T4** | 用**对照**成文 |
| **T5** | **长句装条件和机制，短句下判断** |
| **T6** | 四字格和文言**一次一个** |
| **T7** | 替读者说出反对意见再转折 |
| **T8** | 用条件圈住断言然后说死 |
| **T9** | **具体胜过**「层面、维度、范式」 |
| **T10** | 在**关键数字旁用一句短话停一下**，不新增论断 |
| **T3** | 比喻只取一面、写明取哪一面、一个比喻用到底、**不当论据** |

**⛔ 不要的"文采"**：抒情、拟人叙述、造势排比、强化副词、升华、拿比喻当论据、追求平仄、换说法求变化、卖关子、死喻黑话、四字格连排、用文言替代白话

## 十、交付前复核清单（**9 条，逐条过**）

```
1. 信息守恒      数字/公式/引用/术语/限定词/否定/归因逐一对过；能脚本比对就用 diff
2. 行文          只读每段前两句，论证串得起来；节尾给的是判断（不能从标题猜出来）
3. 口癖          强信号逐项查过；命中处逐个看过上下文
4. 标点          每个分号说得出用途；没新增破折号；短主语后无单独逗号；无为强调加的引号与加粗
                 ⭐ 分号密度 ≤ 每千汉字 1
5. 没造新口癖    替换进去的词没在一页里扎堆
6. 保护清单      一个都没被误改
7. 朗读          不拗口，没有电报句，没有口语词，没有感叹
8. 体裁基准      ⭐ 无「我们」；评分字眼只在完成情况节；每条 1–2 句；指标带条件
9. 排版          ⭐ 图号章-序、图题在下、公式居中+右编号、指数写法统一、图表都被正文引用
```

## 十二、一个改造示例（照着做）

> **改前**（我文档里的真实句子）：
> 「该链路的**价值在于**参数量级可解释、可复核、可迁移，**而非**得到一组'听起来对'的数。」
>
> **问题**：金句式升华（"价值在于…而非…"）+ 空转。
>
> **改后**：
> 「链路每一步的中间结果都保留，参数因此可解释、可复核，也可迁移到其他乐器。」
>
> **改动**：删掉"价值在于/而非"的评论框架，把判断改成**由事实推出的陈述**（B 档金句 A）。

> **改前**：「需要说明的是，表 3.5 中仅串口通路的数值为实测，其余两项为推算与计算值。」
> **改后**：「表 3.5 中仅串口通路的数值为实测，其余两项为推算与计算值。」
> **改动**：删句首评论语（A3）。

> **改前**：「并把每一步的中间结果**落盘留证**。」
> **改后**：「并保留每一步的中间结果。」
> **改动**：删工程腔黑话。
