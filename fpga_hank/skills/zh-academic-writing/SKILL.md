## 〇、改稿六层漏斗（**顺序不能颠倒**）

> 来源：`eloquent-science-zh`

```
1 文档 → 2 章节 → 3 段落 → 4 句子 → 5 词语 → 6 细节
```
**⇒ 结构不稳，绝不打磨字句。**

## 一、三条边界（**最高优先级**）

> 来源：`tuiqiao` 三条边界 + `DEAI_GUIDE` 四条核心原则

| 边界 | 要求 |
|---|---|
| **信息守恒 / 零捏造** | 数字、公式、引用、术语、限定词、否定、条件、归因，**一个不增一个不减**。绝不新增数据、指标、对比结论、新断言、新引用。缺证据标 `【待补证】` |
| **语体不降级** | 正式平实的现代书面语。不加"说白了""讲真"，不加感叹号，不写反问 |
| **不造新口癖** | 同一替换词**一页出现三次以上**就换一种改法 |
| **语法保真** | 改稿只动普通段落文字、章节标题、图表标题文字；⛔ 不动公式、引用键、标签、代码 |

## 二、⭐⭐ 去 AI 化：五类痕迹（**来源：DEAI_GUIDE**）

### 类别 1：空话与口号
| ❌ | ✅ |
|---|---|
| 显著提升 | 将 MAE 降低了 X% |
| 全面系统 | 分析了 X、Y、Z 三方面 |
| 有效解决 | 相比基线提升 X% |
| 重要意义 | 使 X 任务成为可能 |
| 鲁棒性好 | 在噪声环境下保持准确 |
| 新颖方法 | 在 X 基础上引入 Y |

### 类别 2：过度确定
| ❌ 绝对化 | ✅ 限定化 |
|---|---|
| 显而易见 | 实验结果表明 |
| 毫无疑问 | 可认为 / 据此推断 |
| 必然 | 在本文设置下倾向于 |
| 完全 / 总是 / 从不 | 在实验观察范围内 / 极少观察到 |

### 类别 3：机械排比
❌ "该方法**快速、准确、高效**。" ⇒ ✅ "该方法处理速度达 1000 样本/秒，准确率 95%。"
**句式排比（C2）**：**连续 3 句以上开头相同（前 2–4 字相同）** ⇒ 改
❌ "本文提出了A方法。本文设计了B模块。本文实现了C框架。"

### 类别 4：模糊量化
| ❌ | ✅ |
|---|---|
| 大量研究 | 三项近期研究 [1-3] |
| 多次实验 | 在 X、Y、Z 三个数据集上 |
| 大幅提升 | 提升了 12% |
| 绝大多数 | 78% 的案例 |

### 类别 5：模板引言
❌ "随着科技的飞速发展…" ｜ ❌ "时间序列预测是一个具有重要应用价值的课题。"
⇒ ✅ 直接从具体问题背景入手，或给出具体引用

### 类别 5b：⭐ AI 填充连接词（**C1，句首特征词**）
| ❌ 删除 | 处理 |
|---|---|
| 总之 / 综上所述 | 删，直接陈述结论 |
| 不可否认的是 / 值得注意的是 / 需要指出的是 | **删**，把内容直接作主句 |
| 不难发现 / 众所周知 | 删，让读者从数据自行判断 |
| 毋庸讳言 | 删，直接陈述观点 |

**⇒ 检测法：删掉后句子仍完整 ⇒ 该删。**

### 类别 6：⭐ 堆叠式并列引用（**引言/文献综述**）
❌ "许多学者对此进行了研究 [1],[2],[3],[4],[5]。"
✅ "Smith 等人 [1] 提出了 X 方法，在 A 场景取得 Y。Jones [2] 在此基础引入 Z，但受限于 B。"
**规则**：
- **同一句并列引用 ≤ 2 个**（公认事实的背景陈述除外）
- **每篇被引文献至少附一句**对其贡献/方法/局限的描述
- 优先**叙述性引用**而非括号堆砌
- 文献综述**按方法/范式分组**，组内逐篇讨论差异

## 三、⭐⭐ 段落逻辑：AXES 模型

> 来源：`academic-writing-skills`

一段一个议题，最佳 **4–8 句**。段落需具备：
```
A (Assertion)     主题句：本段主张
X (eXample/eXplain) 展开：机制或例证
E (Evidence)      证据：数据、引用、实验
S (Significance)  收束：对本章主线的作用
```
**段落病征**：
- 单句成段
- 段内主语反复更换
- 连续 3 段无任何数字/公式/判据 ⇒ 该段无信息
- 段末加"综上所述，本节实现了…" ⇒ 删

## 四、⭐⭐ 行文（**F 系列**）

| 编号 | 规则 |
|---|---|
| **F1/F5** | 开头**直接进入事实或有代价的问题**；新概念**先例子，再定义，再形式化** |
| **F2** | 旧信息在句首，新信息在句尾；前句结尾接成后句开头 |
| **F3** | 一段之内**主语尽量不换** |
| **F4** | 一段一个议题，**要点落在前两句** |
| **F7** | ⭐ **枚举写进句子**，不预告"有三个观察"再排"第一第二第三" |
| **F9** | 段间靠**复述上段末尾名词**衔接；删元话语（"接下来我们将介绍"）|
| **F10** | ⭐ 节尾**给判断**（边界、代价、反直觉推论、留给下节的问题）；**不把各段挨个缩写，不升华** |
| **F11** | 章节回指用括号，**紧跟它支撑的说法** |

### ⭐ 标题导语（来源：`latex-thesis-zh`）
> **每一章、每一节、四级标题之后，都要先写导语**，再进入小节内容。
**⇒ 检查法：标题后第一段是否交代了"本节解决什么"** —— 但**不要写成"本节将介绍…"式元话语**，而是直接给判断。

## 五、用词与句法（**W 系列**）

| 编号 | 规则 |
|---|---|
| **W1** | 万能动词 + 抽象名词**还原成动词**：「进行重排序」→「重排」；「实现了提升」→「提升了」 |
| **W2** | 「对应」「具有」「存在」「扮演…角色」换成**真实关系** |
| **W4** | 「被」默认去掉；「被称为」→「称为」 |
| **W5/W7** | 删话题壳（「对于…来说」「从…角度看」「在…方面」）|
| **W6** | 「通过……使」会**吞掉主语** |
| **W8** | 句首「作为 X」的 X **必须就是主语** |
| **W9** | 长前置定语**拆成后置小句** |
| **W10** | 「这一 + 名词」→「这个」「这种」 |
| **W11** | 不计数、不引入新对象的「一个」**删掉** |
| **W12** | 硬造的「性」「化」「度」**改回形容词** |
| **W16** | 「正是」「恰恰」「格外」「尤其」**先删掉念一遍** |
| **W17** | 「便」「之」「其」「此」成堆时换白话 |

**拆长句**：**超过 50 字**的句子拆分。

## 六、标点（**PN 系列，GB/T 15834—2011**）

| 规则 | 要求 |
|---|---|
| **破折号** | 只用于正文里的解释说明，**不制造揭晓式停顿** |
| **冒号** | 一句之内不套用两个 |
| **分号** | 只用于 ① 内部有逗号的并列分句 ② 冒号后的分项列举 |
| ⭐ **阈值** | **全文每千汉字超过一个分号就逐个查用途** |
| **PN16** | ⭐ **短主语后不单独加逗号** |
| **引号** | 不为强调而加 |
| **中英混排** | 中文与英文、数字之间**加空格** |

## 七、⭐ 保护清单（**看着像毛病、其实该留**）

> 来源：`tuiqiao`

```
下定义的「即」「称为」与术语首现加粗
同一术语一名到底（为避重复换词，读者会以为换了东西）
证据性限定（通常、可能、几乎、据……报告）
决定真假的「之一」、限制性定语、量词「存在」、计数和引入新对象的「一个」、
  消歧的「被」、实验条件「在……上」
已成术语的「性」「化」「度」
推理里的「因此」「所以」
真实顺序里的「首先」「第一」
纠正读者真会有的误解的「不是 A，而是 B」
带来新推论的「这意味着」
分号的正当用法
交代证据来源的主语和动词
段首加粗小标题、章首导读、章末小结、交叉引用
被动、名词化、长句、句内真排比、问句、比喻本身
引用的原文、代码、提示词一律照录
```
**⛔ 已被推翻、不能据此改**：句长不够参差、同一名词反复出现、被动和名词化本身、三项并列、问句和比喻本身

## 八、⭐ 交付协议（**来源：`academic-writing-skills`**）

改稿建议用**逐条批注**格式，**检查结果与建议改写分开陈述**：
```latex
% <模块> (L##) [Severity: Critical|Major|Minor] [Priority: P0|P1|P2]: <问题摘要>
% 原文：<原句>
% 改后：<改句>
% 理由：<一句理由 + 规则编号>
% ⚠️ [待补证]: <需要证据支撑的断言>
```
| Severity | 含义 |
|---|---|
| **Critical** | 阻塞交付（编译失败、缺必需章节、数字自相矛盾）|
| **Major** | 显著影响质量（逻辑断裂、格式不合规）|
| **Minor** | 润色级（用词、风格一致性）|

## 九、⭐⭐ 本项目体裁基准（**从三份往届获奖作品实测**）

### 9.1 人称与叙述
| 用 | 不用 |
|---|---|
| **本系统 / 本设计 / 本作品 / 项目** | ⛔ **我们** |
| 客观陈述 | ⛔ 心理活动（"我们最初以为…"）|
| 数据说话 | ⛔ 失败叙事 |

**⇒ 教训/反思只出现在「心得体会」一节，客观表述、具体到事。**

### 9.2 ⛔ 评分话术的位置
```
⛔ 全文任何位置不得出现「评分 / 分数 / 拓展① / 红线」
✅ 只允许在【完成情况】一节集中交代做到与没做到
```

### 9.3 ⛔ 不要发明参考文档里没有的结构
```
本章数据来源表 ｜ 摘要/关键词页 ｜ 「赛题要求与章节对照」附录 ｜ 交代性前言 ｜ 自我评价句
⇒ 三份往届参考里【都没有】，一律不加
```

### 9.4 五个固定句式
```
设计目的 ：为了/面向 <问题> …… 本设计旨在开发 <什么系统>，主要目的如下：
           （N）<短语>：<一句话>；
应用领域 ：<一句引导语>：（N）<领域名>：<使用者>可以<做什么>；
技术特点 ：本系统的主要技术特点有：（N）<特点名>：<基于什么>，<实现了什么>，<量化收益>；
性能指标 ：本系统的关键性能指标如下：<指标名>：<在什么条件下>达到 <数值>。
创新点   ：（N）<名称>：<做了什么，用了什么手段>。<因此带来的好处>。
```
**五条硬约束**：① 每条 1–2 句，原理细节留给正文模块章 ② 指标不提前出现 ③ 数字必带条件 ④ **弱指标照写** ⑤ **指标只呈现数据**，不写依据

## 十、⭐ 排版规格（**详版见 `.dsh/skills/docx-editor-cn/`**）

| 项 | 本项目（往届实测） | 上游（学术通用） |
|---|---|---|

| 二/三级 | 黑体 12 pt | 14 / 12 pt |

## 十一、四条工具纪律（**本项目实证**）

| # | 纪律 |
|---|---|
| **1** | **含中文的 `.ps1` 必须 UTF-8 with BOM**；`.md`/`.v`/`.tcl` 无 BOM |
| **2** | **`Set-Content -Encoding UTF8` 在 PS 5.1 会加 BOM** ⇒ 用 `File.WriteAllText(..., UTF8Encoding($false))` |
| **3** | **PowerShell 变量名大小写不敏感**（`$GEN` 与 `$gen` 同一个）|
| **4** | ⭐ **`Get-Content` 按 GBK 解码 UTF-8 中文时会吞换行** ⇒ 数行数必须用 .NET 或 Python |

## 十二、交付前复核（**10 条**）

```
1  信息守恒    数字/公式/引用/术语/限定词/否定/归因逐一对过；无新增数据或断言
2  AXES        每段前两句能否串起论证；段内主语是否稳定
3  去 AI 化    五类痕迹逐项查；C1 填充连接词；C2 句式排比；类别 6 引用堆叠
4  标点        每个分号说得出用途；分号密度 ≤1/千字（列表项不计）；短主语后无逗号
5  保护清单    一个都没被误改
6  朗读        不拗口，无电报句，无口语，无感叹
7  体裁基准    ⛔ 无「我们」；评分话术只在完成情况；每条 1–2 句；指标带条件；
               无自造结构（数据来源表/摘要页/对照附录）
8  标题导语    每章每节标题后有导语段
9  排版        图号连续唯一；图题在下、表题在上；公式居中+右编号；指数统一；
               每张图表都被正文引用
10 交付格式    Critical/Major/Minor 分级；检查结果与建议改写分开
```
