## 一、 中文科研写作与去 AI 化规范

在撰写竞赛技术报告、毕业论文或技术文档时，严格遵守以下去 AI 化与学术表达准则：

### 1.1 三条最高边界
| 边界 | 具体要求 | 违规案例与修正 |
|---|---|---|
| **信息守恒 / 零捏造** | 事实、数字、公式、符号、引用、术语、限定词，**一个不增一个不减**。绝不主观推断未经实测的数据。 | ❌ "延迟大幅下降" ➔ ✅ "内部流水线延迟确定为 3.85 µs（192 个时钟周期）" |
| **语体严肃客观** | 正式平实的现代科技书面语。不写反问句，不用感叹号，杜绝口语化表达。 | ❌ "说实话，这个效果棒极了！" ➔ ✅ "输出音频谐波失真度低于 0.8%，频带平坦度满足要求。" |
| **人称与叙述基准** | 全文统一采用第三人称客观叙述（**本系统 / 本设计 / 本作品**），**严禁使用“我们”**，严禁描写心理活动。 | ❌ "我们最初尝试了方案A，后来我们发现方案B更好" ➔ ✅ "系统最初评估了方案A，经对比测试最终选用方案B。" |

### 1.2 彻底消除 AI 痕迹的五大特征
1. **消除空洞口号**：
   - ❌ 显著提升 / 全面系统 / 有效解决 / 具有极其重要的意义 / 鲁棒性好
   - ✅ 改用量化数据表达：“将延迟缩短至 3.85 µs”、“支持 32 路独立声部并发”、“在 97.656 kHz 采样率下保持信噪比 92 dB”。
2. **消除绝对化与过度确定**：
   - ❌ 显而易见 / 毫无疑问 / 必然 / 总是 / 从不
   - ✅ 改为限定化客观陈述：“实验测量表明”、“据此推断”、“在当前 50 MHz 主时钟约束下倾向于”。
3. **消除机械排比句**：
   - ❌ "该设计快速、稳定、高效。"
   - ❌ 连续三句以上采用相同句首（如连续三句均以“本设计实现了...”开头）。
   - ✅ 句式长短交替，前后呼应。
4. **消除 AI 填充连接词**：
   - ❌ **删除**句首无实义填充词：“不可否认的是”、“值得注意的是”、“需要指出的是”、“毋庸讳言”、“综上所述”、“总而言之”。
   - 规则：如果一个词删掉后句子原意完整，则坚决删除！
5. **消除模板化引言**：
   - ❌ "随着信息技术的飞速发展与电子乐器的日益普及..."
   - ✅ 直接从具体工程痛点切入：“传统电子乐器普遍依赖通用微控制器（MCU/DSP）串行执行多复音音频算法，当复音并发数增加时，中断调度开销易引发毫秒级发声滞后与欠载破音。”

### 1.3 AXES 段落展开模型
正文技术段落推荐遵循 AXES 黄金结构，每段 4～7 句为宜：
- **A (Assertion) 主题句**：段首第一句直接亮出本段核心设计或结论；
- **X (eXplain) 原理解释**：阐明物理机制、算法公式或硬件逻辑流水线；
- **E (Evidence) 数据证据**：给出实测数字、示波器波形图、频谱测试数据或资源消耗表；
- **S (Significance) 收束总结**：指出该设计对系统整体指标达标的作用与边界。

### 1.4 竞赛评审特殊纪律
- **盲审合规**：全文绝对不得出现任何高校名称、学院名称、团队成员姓名或导师信息！
- **行话过滤**：**正文严禁出现“评分/分数/拓展①/红线”等竞赛规则词汇**，必须表述为技术要求与实测性能对账，保持学术严谨性。

## 二、 科技图表绘制规范与配方

### 2.1 图型选择准则（按数据与目的选型）
- **实测取证图（最高优先级）**：示波器实拍图、音频分析仪 FFT 频谱图、7寸大屏真机照片、ModelSim 仿真时序波形。
- **系统架构图**：顶层微架构拓扑图、数据通路与控制流水线图，必须信号流向明确、关键信号线标注完整。
- **参数趋势与对比图**：折线图（用于包络衰减、频率响应）、三线表（用于性能对账、资源占用统计）。

### 2.2 配色方案（学术标准）
| 配色体系 | 主色 (Primary) | 次主色 (Secondary) | 强调色 (Accent) | 灰阶背景 (Muted) |
|---|---|---|---|---|
| **学术深蓝** | `#1F3B73` (Navy) | `#2E5A9E` (Steel) | `#E64B35` (Coral Red) | `#F2F4F8` / `#666666` |
| **Nature 典雅** | `#3C5488` (Indigo) | `#4DBBD5` (Teal) | `#E64B35` (Brick) | `#00A087` (Emerald) |
| **高对比实测** | `#003399` (Blue) | `#009900` (Green) | `#CC0000` (Red) | `#333333` (Charcoal) |

### 2.3 Python Matplotlib 规范出图配方（300 DPI）
```python
import matplotlib.pyplot as plt
import numpy as np

# 1. 字体与画布设置（ASCII 坐标轴，300 DPI 导出）
plt.rcParams['font.sans-serif'] = ['DejaVu Sans', 'Arial']
plt.rcParams['axes.unicode_minus'] = False
plt.rcParams['figure.dpi'] = 300

fig, ax = plt.subplots(figsize=(7.5, 4.2), constrained_layout=True)

# 2. 绘制数据曲线
x = np.linspace(0, 10, 500)
y1 = np.exp(-0.3 * x) * np.sin(2 * np.pi * 0.8 * x)
ax.plot(x, y1, color='#1F3B73', linewidth=1.8, label='Synthesized Envelope')

# 3. 坐标轴与网格优化
ax.set_xlabel('Time (ms)', fontsize=10.5, fontweight='bold', color='#222222')
ax.set_ylabel('Amplitude (normalized)', fontsize=10.5, fontweight='bold', color='#222222')
ax.grid(True, linestyle='--', alpha=0.5, color='#CCCCCC')
ax.legend(frameon=True, facecolor='#FFFFFF', edgecolor='#E0E0E0', fontsize=9.5)
ax.spines['top'].set_visible(False)
ax.spines['right'].set_visible(False)

# 4. 导出高清矢量/位图
plt.savefig('envelope_curve.png', dpi=300, bbox_inches='tight')
plt.close()
```

## 三、 竞赛技术文档格式与排版规范

### 3.1 页面与版心尺寸
- **纸张**：标准 A4（210 mm × 297 mm）
- **页边距**：上 2.54 cm，下 2.54 cm，左 2.80 cm，右 2.60 cm
- **正文字体**：中文宋体（小四号 12 pt 或五号 10.5 pt），西文/数字 Times New Roman，行距 1.25~1.5 倍，首行缩进 2 字符

### 3.2 标题与层级结构
- **大标题**：小二号黑体（18 pt），居中，段前段后 18 pt
- **一级标题（第一部分 ...）**：三号黑体（15 pt），加粗，段前 14 pt，段后 6 pt
- **二级标题（1.1 ...）**：四号黑体（13 pt），加粗，段前 10 pt，段后 4 pt
- **三级标题（2.2.1 ...）**：小四号黑体（11.5 pt），加粗，段前 6 pt，段后 2 pt

### 3.3 图表排版规范
- **图题**：五号黑体/宋体（9.5 pt），**置于图下方**，居中对齐，格式如：“图 1-1 乐器系统实机运行整体视听反馈图”；
- **表题**：五号黑体/宋体（9.5 pt），**置于表上方**，居中对齐，格式如：“表 1-1 主要技术与性能指标实测汇总表”；
- **表格样式**：采用标准科研**三线表**（顶线与底线 1.5 pt 粗实线，栏目分割线 0.75 pt 细实线，无竖线）。

## 四、 GitHub 协同与分支同步纪律

本仓库与远端仓库实行严格的双代理协作协议，每次开工与提交前必须遵守以下规程：

### 4.1 每次开工的第一动作：拉取远端
```powershell
# 1. 检查远端是否有队友最新更新
git -C "26Embedded" fetch origin

# 2. 对比本地 HEAD 与 origin/main 领先/落后提交数（"0 0" 表示完全一致）
git -C "26Embedded" rev-list --left-right --count HEAD...origin/main

# 3. 若有更新，采用 rebase 模式安全拉取
git -c core.longpaths=true -C "26Embedded" pull --rebase origin main
```

### 4.2 提交流程与边界防线
- **写作用域安全**：只向 `26Embedded/fpga_hank/` 提交交付成果；**绝对禁止修改队友目录**（`fpga_spark/`, `fpga_hardware/`, `fpga_ben/` 等严格只读）；
- **排除二进制大文件**：绝不提交 `.fs` 位流大文件、仿真 `.wlf` 文件或 `eda_proj/` 临时综合产物；
- **提交与推送**：
  ```powershell
  git -C "26Embedded" add fpga_hank/
  git -C "26Embedded" commit -m "docs: 详细清晰说明本次更新的具体技术模块"
  git -C "26Embedded" push origin main
  ```
- **记录进度**：提交后在 `COLLAB/PROGRESS.md` 中追加记录，确保两代理与队友信息无缝衔接。
