## 1. 两个模式：先听声音，再取证

正式顶层 `rtl/top.v` 有一个**编译期开关** `TEST_MODE`，决定这个位流是干什么的：

| 模式 | `TEST_MODE` | 按键作用 | 音色 | 用途 |
|---|---|---|---|---|
| **演奏模式** | **0** | **真按键驱动发声** | 按键切换 4 种 | ★ **先烧这个，确认能出声** |
| **测试模式** | **1**（当前默认） | 无效（32 路恒发声） | 锁定纯正弦 | ★ **频谱取证：数 32 根谱峰** |

⚠️ **当前仓库里 `top.v` 的默认值是 `TEST_MODE = 1`**（测试模式）。
所以**想用按键演奏，必须先把它改成 0 再构建一次**。

### 怎么切换

编辑 `rtl/top.v`，找到模块参数：

```verilog
module top #(
    parameter integer TEST_MODE = 1,   // ← 演奏模式改成 0
    parameter integer BCK_DIV   = 1
)(
```

改成 `0`，然后重新构建：

```powershell
& "F:\Gowin\Gowin_V1.9.12.04_x64\IDE\bin\gw_sh.exe" tools\gowin\build.tcl
```

产物：`eda_proj\fpga_hank\impl\pnr\fpga_hank.fs`（约 33 MB）。

> ★ **不想自己构建？仓库里已经备好了两个位流**，直接烧即可：
> - `out\bitstream\fpga_hank_TESTMODE0_演奏模式.fs`（★ 演奏，先烧这个）
> - `out\bitstream\fpga_hank_TESTMODE1_测试模式.fs`（频谱取证）
>
> 两种模式**都已实测综合通过**（时序零违例、12 引脚全约束），
> 详见 [预先构建的位流.md](预先构建的位流.md)。

> ⚠️ **改 `BCK_DIV` 时必须同步重新生成 `tone_bank.v`**，否则音高会整体偏移：
> `python tools\gen\gen_tone_bank.py --write --bck-div <同一个值>`
> （`TEST_MODE` 不需要重新生成任何东西。）

## 2. 三个按键分别干什么（演奏模式）

| 按键 | 引脚 | 按住/按下会怎样 |
|---|---|---|
| **key** | `AB13`（板载） | **按住 = 发声**（32 路齐发）；松开 = 进入释放段 |
| **key2** | `Y12`（板载） | **每按一下换一种音色**，4 种循环（正弦→锯齿→方波→三角） |
| **key_pitch** | `Y22`（**PMOD 排针，需自备一个按钮外接**） | **每按一下升 1 个半音**（-8~+7 循环，按 8 下回到原调） |

> ⚠️ **`Y22` 是 PMOD 排针上的脚，板上没有现成按钮。**
> 需要自己接一个按钮：一端接 `Y22`，另一端接 **GND**。
> 引脚已配置内部上拉（`LVCMOS33 / PULL_UP`），**按下 = 拉到 0**，无需外接电阻。
> **这正是赛题要求的「自研交互形态」**（不买现成键盘，自己接一个按钮）。
>
> ⚠️ 同一块板上 `Y22` 在**冒烟测试**里是**输出**（`DBG_KEY` 打标脚），
> 在**正式顶层**里是**输入**（变调键）。两者分属不同位流，不冲突。

**演示顺序建议**：
1. 按住 `key` → 听到持续音（正弦）
2. 按住 `key` 不放，按 `key2` → **音色变了，但声音不断**（这就是"三维度独立可控"）
3. 按住 `key` 不放，按 `key_pitch` → **音高升半音**
4. 松开 `key` → 声音平滑衰减消失（释放段约 63 ms）

## 3. 烧录（命令行的确切用法）

`tools\gowin\program.ps1` 的参数是从**本机 `programmer_cli.exe --help` 实测**得到的，
不是抄网上的：

```powershell
# 只扫描，确认缆线与器件被识别（含排查清单）
... -File tools\gowin\program.ps1 -Mode scan

# 下载到 SRAM —— 易失、不改 Flash。第一次上板一律用这个
... -File tools\gowin\program.ps1 -Mode sram

# 不需要板子！让烧录工具解析 bitstream 并生成 JTAG 向量文件，验证 bitstream 本身有效
... -File tools\gowin\program.ps1 -Mode verify

# 确认无误后写入外部 Flash（永久、上电自动运行）
... -File tools\gowin\program.ps1 -Mode flash
```

### 为什么第一次一定要用 SRAM

**SRAM 下载是易失的** —— 掉电即丢，**不改动板上的 Flash**。
即使这个位流有问题，也不会把板子刷成"一上电就跑坏程序"的状态。
**反复调试阶段一律用它。**

### 已验证的事实（不需要板子就能确定的部分）

| 项 | 结果 |
|---|---|
| 烧录工具存在 | ✅ `programmer_cli.exe` V1.9.12.04 build 2743 |
| **支持本板器件** | ✅ 器件列表含 **`GW5AST-138C`** |
| **bitstream 被判为有效** | ✅ `-Mode verify` 成功生成 SVF：**9 258 660 B / 65 694 行**，文件头提取出 **`Device ID = h0001081B`** |
| **仍未验证的** | ⬜ **实际的物理 JTAG 连接与下载** —— 必须插板才能确认 |

## 4. 如果没声音：按这个顺序查

| # | 检查 | 怎么确认 |
|---|---|---|
| 1 | **功放使能** `PA_EN`(AB16) 是否为低 | 代码里常拉低；硬件上它是**低有效**，不拉低则功放不出声 |
| 2 | **耳机插对孔** | 板上有 3.5 mm 耳机口；也可接 2 路 3W 扬声器座 |
| 3 | **板子是否真的在跑新位流** | 用 **SRAM 下载**而不是 Flash（避免烧了旧 Flash） |
| 4 | **是不是烧了测试模式位流** | 测试模式下按键**无效**，但会持续发声（32 路），插耳机应能听到 |
| 5 | **供电是否够** | 单口 USB 供电会掉电重启；建议 USB3.0 + DEBUG-USB **双路供电**或 12V DC |
| 6 | **`led[0..3]` 有没有变化** | 见下方 LED 表（低有效） |
| 7 | 仍不行 | 转 [上板验证指南.md](上板验证指南.md) 用 **S0→S6 分级冒烟**二分定位 |

### LED 的含义（低有效，代码里已定义）

| LED | 引脚 | 亮/闪表示 |
|---|---|---|
| `led[0]` | T18 | **闪烁 = 逻辑在跑**（心跳，分频计数高位） |
| `led[1]` | R18 | 亮 = **采样帧在流动** |
| `led[2]` | R17 | 亮 = **有音符在发声**（任一 gate 为高） |
| `led[3]` | P16 | 亮 = **包络在非静音阶段**（说明 ADSR 真的在工作） |

> 按 `key` 时应看到 `led[2]`、`led[3]` 变化；`led[0]` 应一直在闪。
> 若 `led[0]` 不闪 ⇒ 时钟或配置没生效，问题在烧录/时钟，不在音频通路。

## 5. 测试模式：数出 32 根谱峰（赛题必备交付物）

这是赛题**明确要求**的必备项，不能省。

### 5.1 先确认判据工具本身没坏（不需要硬件）

```powershell
# 用已有的仿真证据跑一遍判据，应输出 PASS（32/32 命中）
python tools\verify\check_peaks.py --file docs\evidence\tone_samples_pitch0.txt `
    --format samples --fs 97656.25 --count 32 --start 200 --step 200
```

### 5.2 用真板录音

1. 烧 `TEST_MODE = 1` 的位流（测试模式）
2. 耳机口用音频线接到电脑声卡 Line-in（或直接用手机录）
3. **录 5 秒以上**，存成 wav
4. 转成样本文件后跑同一个判据：

```powershell
# fs 换成你声卡【实际】的采样率（常见 44100 / 48000，不要照抄 97656.25）
python tools\verify\check_peaks.py --file <录音样本.txt> --format samples `
    --fs <你的声卡采样率> --count 32 --start 200 --step 200
```

⚠️ **`--fs` 必须填录音设备真实的采样率**，否则频率轴整体缩放，判据会把全部峰判成"杂散"。
（仿真证据用的是 FPGA 的输出采样率 97 656.25 Hz，录音时不是这个数。）

**期望结果**：32 根独立谱峰，频率约 **200 / 400 / 600 … 6200 / 6400 Hz** 均匀分布。
