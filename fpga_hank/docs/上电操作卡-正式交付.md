## 1. 三个模式：先听琴声 → 再放歌 → 最后取证

正式顶层 `rtl/top.v` 有一个**编译期开关 `MODE`**（**第 40 行**），决定这份位流是干什么的：

| MODE | 位流文件 | 大小 / `sha256`(前16) | **`User Code`** | 用途 |
|---|---|---|---|---|
| **0** | `MODE0_演示模式_放歌.fs` | 38 814 719 B / `8C6A0208320009F8` | **`0x0000C7B0`** | ★ **按键放歌**（小星星/欢乐颂/铃儿响叮当/致爱丽丝…） |
| **1** | `MODE1_电脑控制.fs` | 40 089 599 B / `DC5E68AAC44D364F` | **`0x0000F2CB`** | ★★ **电脑当钢琴弹**（**用户最看重的功能**） |
| **2** | `MODE2_测试模式_32谱峰.fs` | 34 840 489 B / `68F7FFD22A9B1B18` | （重建版） | ★ **频谱取证：数 32 根谱峰**（赛题必备） |

**完整指纹与证据强度**见 [BITSTREAM-FINGERPRINTS.md](BITSTREAM-FINGERPRINTS.md)。

### 1.1 ⭐ 各模式的按键作用（**已按 `top.v` 实测核实**）

| 按键 | 引脚 | MODE=0 放歌 | MODE=1 电脑 | MODE=2 测试 |
|---|---|---|---|---|
| `key` | `AB13`（板载） | **播放 / 停止** | —（音符由电脑发） | 无（**恒发声**） |
| `key2` | `Y12`（板载） | **切歌** | **切效果器**（旁路→延迟→合唱→混响） | **切音色** |
| `key_pitch` | `Y22`（**PMOD，需外接按钮**） | — | — | **每按一下升 1 个半音** |

> ⚠️ **`Y22` 板上没有现成按钮**，需要自己接：一端接 `Y22`、另一端接 **GND**。
> 引脚已配内部上拉（`LVCMOS33 / PULL_UP`），**按下 = 拉到 0**，无需外接电阻。
> **这正是赛题要求的「自研交互形态」**（不买现成键盘，自己接）。
> ⚠️ 同一块板上 `Y22` 在**冒烟测试**里是**输出**（`DBG_KEY`），在**正式顶层**里是**输入**。两者分属不同位流，不冲突。

> ⚠️ **演示模式（MODE=0）一首放完是【单曲循环】**，不自动跳下一首 ——
> 这样 `key2`（切歌键）的职责才不会被自动行为掩盖。

### 1.2 怎么切换模式

编辑 `rtl/top.v` **第 40 行**：
```verilog
parameter integer MODE = 0,     // 0=演示放歌  1=电脑控制  2=32峰测试
```
改完**必须重新构建**（`MODE` 是**编译期参数**，不是运行期切换；每个模式一份独立位流，不需要的通路会被优化掉）。

> ⚠️ **改 `BCK_DIV` 时必须同步重新生成 `tone_bank.v`**，否则音高整体偏移：
> `python tools\gen\gen_tone_bank.py --write --bck-div <同一个值>`（**`MODE` 不需要重新生成任何东西**）。

### 1.3 🔴 **位流不进版本库 —— 你要自己构建**

`fpga_hank/out/` **整目录被 gitignore**（双判据实测：`git check-ignore --no-index` = IGNORED；`git ls-files fpga_hank/out/*` = **0**）。
**⇒ 克隆后 `out\bitstream\` 是空的。** 完整步骤见 [../README.md](../README.md) §2.1：

```powershell

& "F:\Gowin\Gowin_V1.9.12.04_x64\IDE\bin\gw_sh.exe" "tools\gowin\build.tcl"
# ③ 产物（★ 每次构建都会覆盖同名文件）
#      eda_proj\fpga_hank\impl\pnr\fpga_hank.fs
# ④ ★★ 立刻归档，否则下次构建就覆盖了（MODE=2 的位流就是这么丢过一次）
```

## 2. ⭐★ 电脑钢琴（MODE=1）—— 用户最看重的功能

**电脑只发"弹了哪个键"的数字命令，声音 100% 由 FPGA 实时合成。**

```powershell
# ① 烧 MODE=1 位流
powershell -NoProfile -ExecutionPolicy Bypass -File tools\gowin\program.ps1 -Mode sram `
    -Fs out\bitstream\MODE1_电脑控制.fs

# ② 建电脑端环境（只需一次；._tools\venv 不在库里）
python -m venv _tools\venv
.\_tools\venv\Scripts\python.exe -m pip install -r host\requirements.txt

# ③ 启动虚拟钢琴
.\_tools\venv\Scripts\python.exe host\piano_gui.py

# ④ 界面里：串口选 COM9 → 点「连接」
# ⑤ 调试框原样发十六进制："90 45 64"  ⇒ 应听到 A4 = 440 Hz
# ⑥ 鼠标点琴键；或键盘：ASDFGHJ = 白键、WETYU = 黑键
# ⑦ 板载按键 key2(Y12) = 切效果器（旁路→延迟→合唱→混响）
```

**自检**（不开界面）：`.\_tools\venv\Scripts\python.exe host\piano_gui.py --selftest` ⇒ **37 项全 PASS**

**协议**（`host/` 与 RTL 必须一致，**单方改动即为 bug**）：
```
NoteOn : 0x90 note vel      （vel = 0 视为 NoteOff）
NoteOff: 0x80 note vel
AllOff : 0xB0 0x7B 0x00     （CC123，实现为连续 128 拍 off_valid）
表情：CC5 滑音时间 / CC65 滑音开关 / CC1·CC77 颤音深度 / CC76 颤音速率 / CC64 延音踏板
```

**⇒ 还可以放 MIDI 文件**（同一个 MODE=1 位流）：
```powershell
.\_tools\venv\Scripts\python.exe host\midi_player.py --port COM9 --file 你的.mid
```

> ⚠️ **已知问题**：MODE=1 有**时序违例 `−4.67 ns`（4159 条路径）**，但**功能实测正常**。
> 分析见 `_research/piano/TIMING-MODE1.md`。**修法（多周期路径约束）尚未清违例。**

## 3. 演示模式（MODE=0）：按键放歌

## 4. 测试模式（MODE=2）：数出 32 根谱峰（**赛题必备交付物**）

> ⚠️ **这个模式的声音就是"一片嗡嗡声"** —— 因为 **32 个正弦同时响（200/400/…/6400 Hz）**。
> **这是赛题要求的取证声，不是故障。** 用户第一次听到时以为板子坏了，其实就是这个。

### 4.1 先确认判据工具本身没坏（不需要硬件）
```powershell

    --format samples --fs 97656.25 --count 32 --start 200 --step 200
```

### 4.2 用真板录音
```powershell
# ① 烧 MODE=2 位流
powershell -NoProfile -ExecutionPolicy Bypass -File tools\gowin\program.ps1 -Mode sram `
    -Fs out\bitstream\MODE2_测试模式_32谱峰.fs
# ② 从麦克风录（本机有 sounddevice + scipy）
python tools\verify\record_audio.py --sec 10 --out out\record\mic1.wav
# ③ 判据（--fs 必须是【你录音设备的实际采样率】，不要照抄 97656.25）
```

## 5. 烧录（命令的确切用法）

`tools\gowin\program.ps1` 的参数是从**本机 `programmer_cli.exe --help` 实测**得到的：

| `-Mode` | 内部操作码 | 作用 |
|---|---|---|
| `scan` | — | 只扫描，确认缆线与器件被识别（含排查清单） |
| **`sram`**（默认） | **2** | **SRAM Program，易失、不动 Flash** ⇒ **首次上板一律用这个** |
| `verify` | 2 + `--svfcreate` | **不需要板子**！解析位流并生成 JTAG 向量文件 |
| `flash` | 9 | exFlash Erase,Program,Verify（**会改写板上 Flash**，上电自动运行） |

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\gowin\program.ps1 -Mode sram `
    -Fs out\bitstream\MODE1_电脑控制.fs
```

### ⚠️ 两个必须知道的点
1. **脚本参数是 `-Mode`，没有 `-Op`。** `op 2` 是**脚本内部**传给 CLI 的（`sram`→2、`flash`→9）。
   **写 `-Op 2` 会直接报"找不到参数"。**
2. **别用操作码 4**（"SRAM Program **and Verify**"）。脚本注释实测记录：
   > **本板（Tang Mega 138K + 板载 FT2232H）的【回读校验通路不可用】**，用 op 4 **必然报
   > `Error: Verify failed of at 0`**，**但位流其实已正确写入**（证据：`User Code` 随位流变化）。
   > ⇒ **这是假失败**；Sipeed 官方文档用的也正是**不带 Verify 的操作码 2**；耗时从 ~106 s 降到 ~21 s。

### 为什么第一次一定要用 SRAM
**SRAM 下载是易失的** —— 掉电即丢、**不改动板上 Flash**。即使位流有问题，也不会把板子刷成"一上电就跑坏程序"。

### 已验证的事实（不需要板子就能确定的部分）
| 项 | 结果 |
|---|---|
| 烧录工具 | ✅ `programmer_cli.exe` V1.9.12.04 build 2743 |
| **支持本板器件** | ✅ 器件列表含 **`GW5AST-138C`** |
| **位流被判为有效** | ✅ `-Mode verify` 生成 SVF：9 258 660 B / 65 694 行，文件头 **`Device ID = h0001081B`** |

## 6. 如果没声音：按这个顺序查

| # | 检查 | 怎么确认 |
|---|---|---|
| 1 | **烧的是哪个模式的位流？** | **最常见的原因**：想弹琴却烧了 MODE=2（恒发声、按键无效）；想听歌却烧了 MODE=1（需电脑驱动） |
| 2 | **耳机插对孔** | 板上有 3.5 mm 耳机口；也可接 2 路 3W 扬声器座 |
| 3 | **板子是否真在跑新位流** | 用 **SRAM 下载**（避免烧了旧 Flash）；看 `led[0]` 是否在闪 |
| 4 | **`MODE=0` 是否按了 `key`** | 演示模式**不按键不发声**（`led[2]` 亮 = 正在放歌） |
| 5 | **`MODE=1` 电脑端连上了吗** | `piano_gui.py` 里串口 **COM9** → 点「连接」→ 调试框发 `90 45 64` 应出 440 Hz |
| 6 | **供电是否够** | **单口 USB 会掉电重启**（灯灭又依次亮）；用 **USB3.0 + DEBUG-USB 双路** 或 **12V DC** |
| 7 | 仍不行 | 转 [上板验证指南.md](上板验证指南.md) 用 **S0→S6 分级冒烟**二分定位 |

> ✅ **功放使能不用查了**：代码里 `assign PA_EN = 1'b0;`（低有效 ⇒ **常开**）。

### LED 的含义（**已按 `top.v` 实测核实**）

| LED | 引脚 | 含义 |
|---|---|---|
| `led[0]` | `T18` | **闪烁 = 逻辑在跑**（心跳）。**不闪 ⇒ 时钟/配置没生效，问题在烧录，不在音频通路** |
| `led[1]` | `R18` | 亮 = **采样帧在流动** |
| `led[2]` | `R17` | **MODE=0：亮 = 正在放歌**；其它模式：亮 = 有音符在发声 |
| `led[3]` | `P16` | 亮 = **包络 / 声部活跃**（ADSR 真的在工作） |
