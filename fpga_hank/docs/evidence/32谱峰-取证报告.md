## 四、复现命令

```powershell
# 1) 跑仿真，导出 out/tone_samples.txt
& "F:\Modelsim_10.7\win64\vsim.exe" -c -do sim\run.do

# 2) 快照（绝不要直接分析活文件）
Copy-Item out\tone_samples.txt docs\evidence\tone_samples_snap.txt -Force

# 3) 判据（--fs 必须写【实际】采样率；写 48000 会全部误判 FAIL）
python tools\verify\check_peaks.py --file docs\evidence\tone_samples_snap.txt `
    --format samples --fs 97656.25 --count 32 --start 200 --step 200
# 期望：exit code 0，输出 "结论: PASS - 检出 32 路独立谱峰"
```

> ⚠️ **`--fs` 是最容易出错的地方**。本项目实测过：`check_peaks.py` 默认 48000，
> 而实际 fs 是 97 656.25 Hz ⇒ 200 Hz 会被读成 98.1 Hz，**32 个峰全部误判 FAIL**。
> 同理 `tools/gen/gen_tone_bank.py --bck-div` 与 `top.v` 的 `BCK_DIV` **必须成对一致**。

## 五、与"无预录音频"合规性的对应

赛题红线：「严禁播放预录 PCM / 预置推流 / 整段录音触发。现场会用频谱 + RTL 代码审查双重验证。」

本工程的合规证据：

| 审查项 | 证据 |
|---|---|
| 有无音频样本 ROM | ❌ 无。工程内**不存在任何 PCM/WAV/音频样本文件** |
| 波形表是什么 | `rtl/synth/wave_rom.v` 是**数学生成的波形系数表**（正弦/带限锯齿/方波/三角波，各 256 项 16 bit），由 `tools/gen/gen_wave_rom.py` 按谐波级数算出，**不是录音** |
| 是否逐样本实时合成 | ✅ 每个采样点由 32 个**独立相位累加器**并行推进、逐路查表、逐路乘包络、求和限幅得出（全部组合/时序逻辑，无 CPU 参与） |
| 有无整段录音触发 | ❌ 无 |
| 32 个谱峰说明什么 | **32 根同时存在、彼此独立的谱峰**，证明存在 32 个独立频率源在**同时**发声 —— 这是预录/回放做不到的（回放只能复现录制时的那一组频率） |
