## 2. ★ 重要发现：测试模式与演奏模式必须分离

**这是本轮最有价值的发现。** 最初的 `tb_spectrum` 直接跑演奏模式（ADSR 门控），
结果是：

```
期望谱峰 32   命中 6   未命中 26       ← 谱峰被门控调制抹掉
```

**原因**：ADSR 的门控会**调制**每个音（起音/衰减/释放都是幅度变化），
调制必然产生边带、把谱峰抹开。这不是 bug，是物理规律。

**所以**：
- **测试模式** = 所有声部恒按住 → 包络进 sustain 后电平恒定 → 谱峰干净
  （`bench_gate.TEST_MODE = 1`，32 个 gate 恒为 1）
- **演奏模式** = 正常 ADSR 门控（`bench_gate.TEST_MODE = 0`，按键驱动）

这与赛题原文完全一致："支持**测试模式**下输出多路不同频率音频，
频谱可观测对应数量独立谱峰"。测试模式本来就是一种特定的工作状态，
不是取巧 —— 它是赛题**明确要求提供**的取证状态。

## 3. 过程中的 4 个真实缺陷（全部"功能看起来正常"）

这一节是本文档最有价值的部分。**四个缺陷都通过了"有波形/有声音"这一关**，
只有用独立手段（逐位解码 / 直方图统计 / 绝对电平 / 频谱）才暴露出来。

### 缺陷 1：最后一路（6400 Hz）缺失 —— 流水线少一拍

**症状**：32 路只有 31 个谱峰，缺失的总是**索引最大的那一路**。

**根因**：`sum` 在某一拍才把第 31 路加进去，而 `mix_out` 在**同一拍**就用旧 `sum` 算完了。

**逐拍实测证据**（capture `rom_val`）：
```
samp_cnt=32 时 rom_val=18037 （第 30 路）
samp_cnt=33 时 rom_val=29447 （第 31 路 = 6400 Hz）
```

**独立复核**：Goertzel 测得 6400 Hz 仅 **−69 dB**（等于没有），确认不是分析判据误报。

**修法**：输出拍必须**推迟到最后一拍累加之后**（`samp_cnt == N_VOICES+1`）。

### 缺陷 2：第 0 路（200 Hz）偏高 9.74 dB —— 地址 MUX 多读

**抓出者**：`fpga-tools` 用**独立直方图统计**（`tb_diag.v`）发现
`voice[0]` 每采样被读 **3 次**、其余各 1 次，`sum` 变成 **34 项**而非 32 项。

**数值印证**：`20·log10(3) = 9.54 dB` ↔ 频谱实测 **9.74 dB** —— 两个独立测量吻合。

**根因**：靠 `samp_cnt` 的边界条件对齐"每一路读一次"在两端各多读了一次。

**修法**：改用**显式状态机** —— `addr_mux` 只在 `0..30` 时 `+1`，到 31 后保持。

**修后复测**：电平离散度 **9.74 dB → 0.82 dB**（判据要求 ≤1 dB）。

### 缺陷 3：32 个峰全部误判 FAIL —— 命令漏了 `--fs`

**抓出者**：`fpga-tools`

`tb_spectrum.v` 头注释原来给的命令漏了 `--fs`，而 `check_peaks.py` 默认 `fs=48000`、
真实是 `48828.125`（差 1.725%）→ 200 Hz 被读成 196.29 Hz。

| 命令 | 实测结果 |
|---|---|
| 照原头注释（无 `--fs`） | **exit 1，命中 0/32** |
| 加 `--fs 48828.125` | **exit 0，命中 32/32** |

### 缺陷 4：87 个杂散 —— 混音缩放系数取小，导致削波

**抓出者**：`check_peaks.py` 的 C3 判据（未预期谱峰）

接上包络后第一次测量：**32/32 命中，但出现 87 个杂散**：
```
杂散: 7399.92 Hz -16.39 dBc
杂散: 7600.34 Hz -19.01 dBc
杂散: 7800.01 Hz -20.64 dBc   ← 一串 200 Hz 整数倍谐波
```

**根因**：`mix_out <= sat16(sum >>> 3)` 只除了 8。而 32 路满幅同相到顶时
`sum ≈ ±1.05e6`，除 8 后是 ±131072，远超 16 bit 有符号范围 → `sat16` 削波 →
削波产生谐波与互调。

**修法**：改回 `>>> 5`（除以 32），使满幅 32 路和落在 ±32768 内。
这正是参考工程注释里"相加前先各自右移"的道理。

**修后复测**：杂散 **87 → 0**。

## 4. ADSR 包络验证（独立 testbench，9/9 通过）

| 断言 | 结果 |
|---|---|
| 1 复位后静音 | ✅ level=0 phase=IDLE |
| 2 按住 → ATK | ✅ |
| 3 ATK → DEC，且进入时接近满幅 | ✅ level=65536 |
| 4 DEC → SUS，电平 = 49152 | ✅ |
| 5 SUS 阶段电平稳定不漂移 | ✅ |
| 6 松开后电平开始下降 | ✅ |
| 7 释放完成 → IDLE，level=0 | ✅ |
| 8 二次触发能重新起音（声部可复用） | ✅ |
| 9 未触发声部恒为 0 | ✅ |

**ADSR 上踩的两个坑（都"看不出问题"）**：

1. **gate 必须是电平而非脉冲**。第一版把 gate 当单拍脉冲，于是"释放"只发生一拍、
   电平只减一个步长就停住 —— 实测 `note_off` 之后电平停在 49152 不动。
   正确语义：gate 高 = 按住（起音/衰减/保持），gate 低 = 松开（释放）。
2. **分频计数器的 always 必须带复位**。改写时漏掉 `rst_n` 判断，`en_div_cnt`
   一直是 `x` → `en_step` 恒为 `x` → 电平永远不动、相位停在 ATK。
   症状是"设计完全不动"，但编译零错误零警告。
3. **测试断言不要用"等固定拍数"**。第一版算错了相位，在 SUS 阶段去断言 DEC
   而误报失败。改为**轮询状态转移**后再断言序列，与具体拍数无关。

## 5. 采样率决策（为什么不是精确 48 kHz）

`fs = 50 MHz / (BCK_DIV × 512)`，取整数 `BCK_DIV = 2` → **48828.125 Hz**（比 48 kHz 高 1.725%）。

**音准由频率字折算补偿，误差为 0**：`频率字 = round(f_target × 2³² / 48828.125)`

这与参考实现 `vdalex/tangmega-138k-fpga-projects` 一致（它在 75 MHz 下用 DIV=49 →
fs=47 831.6 Hz，同样不是精确 48 kHz）。该工程注释明确指出：

> 分频必须是**均匀**的 —— DAC 在每个 WS 边沿转换，帧率就是它的转换时钟；
> 把分数分频"抖动"去平均出 48 kHz 会把抖动直接灌进音频。

## 2. 架构（为什么这样写才符合赛题的"振荡器统计规则"）

赛题规定一个"振荡器"必须同时具备 **独立相位累加器 + 频率调控 + 包络控制**，
且明确 **单个波表采样查表仅计 1 个振荡器**。

```
每个采样周期（fs = 48828.125 Hz，预算 1024 个 clk）：
  samp_cnt=0 : 32 路【独立 32 bit 相位累加器】各自 += freq_word(v)
               addr_mux <= 0
  samp_cnt=1..32 : 每拍 sine_rom 返回一路的值并累加（时分复用一份 ROM）
  samp_cnt=33 : mix_out <= sat16(sum >>> 5)      ← 饱和限幅 + 预缩放
```

- **(1) 独立相位累加器**：`acc[0..31]`，32 个独立 32 bit 寄存器
- **(2) 频率调控**：`freq_word(v)` 每路独立频率字，可运行中改写
- **(3) 包络控制**：测试模式恒定幅度；演奏模式由 `adsr` 逐路提供（待接入）

**诚实说明（写报告时要如实写，不能糊弄评委）**：
本模块用**时分复用一份 `sine_rom`** 来避开 BSRAM 端口冲突，这正是赛题所说
"单波表查表只算 1 个"的情形。32 路计数的依据是 **32 个独立相位累加器 +
32 个独立频率字**，不是"波表份数"。
若要更硬的证据链，可把 `sine_rom` 复制 32 份（每份约 256 LUT，138240 LUT 完全放得下）
做成全并行查表 —— 这是可选优化。

**数值印证**：`20·log10(3) = 9.54 dB` ↔ 频谱实测 **9.74 dB** —— 两个独立测量吻合。

**根因**：靠 `samp_cnt` 的边界条件对齐"每一路读一次"在两端各多读了一次。

**修法**：改用**显式状态机**——`addr_mux` 只在 `0..30` 时 `+1`，到 31 后保持。
不再依赖边界判断。

**修后复测**：电平离散度 **9.74 dB → 0.82 dB**（判据要求 ≤1 dB）。

### 缺陷 3：`--fs` 缺失导致 32 个峰全部误判 FAIL

**抓出者**：`fpga-tools`

`tb_spectrum.v` 头注释原来给的命令漏了 `--fs`，而 `check_peaks.py` 默认 `fs=48000`、
真实是 `48828.125`（差 1.725%）→ 200 Hz 被读成 196.29 Hz。

| 命令 | 实测结果 |
|---|---|
| 照原头注释（无 `--fs`） | **exit 1，命中 0/32** |
| 加 `--fs 48828.125` | **exit 0，命中 32/32** |

**教训**：这类"分析工具默认参数与设计不一致"的坑，会让**达标的结果看起来失败**
（也可能反过来让失败看起来达标）。必须把 `--fs` 写进命令模板。

## 4. 采样率决策（为什么不是精确 48 kHz）

`fs = 50 MHz / (BCK_DIV × 512)`，取整数 `BCK_DIV = 2` → **48828.125 Hz**（比 48 kHz 高 1.725%）。

**音准由频率字折算补偿，误差为 0**：

```
频率字 = round(f_target × 2²³ / 48828.125)     ← 按【实际】fs，不是 48000
```

这与参考实现 `vdalex/tangmega-138k-fpga-projects` 的做法一致（该工程用
DIV=49 @75 MHz → fs=47 831.6 Hz，同样不是精确 48 kHz）。该工程注释明确指出：

> 分频必须是**均匀**的 —— DAC 在每个 WS 边沿转换，帧率就是它的转换时钟；
> 把分数分频"抖动"去平均出 48 kHz 会把抖动直接灌进音频。

**代价**：绝对音高与标准 48 kHz 设备差 −0.30 半音。对本赛题（频谱数谱峰、听感演示）无害。
**收益**：彻底消除分数分频带来的一整类 bug（实测曾连续两版都调不对）。
