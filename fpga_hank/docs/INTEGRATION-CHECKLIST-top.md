## 2. 🔴 三个必须处理的集成陷阱（都有实测依据）

### 2.1 模式切换会留挂音 —— `top.v` 必须自己发全关
**来源**：`song-demo` TB 阶段 8 实测（48 PASS 中的一条）

> `song_player` **复位时不补发 all-notes-off**（这是对的：复位是全局的，下游同时复位）。
> **但它没有任何输入告诉它"自己被切走了"** —— 它只对自己**被停止**负责。

**⇒ 若用多路选择在"演示 ↔ 演奏/电脑"之间切换而不复位，切走那一刻若有音在响，
`top.v` 必须主动发全关（或复位下游），否则留挂音。**

### 2.2 全关语义是「连续 128 拍 `off_valid`，`off_note` = 0..127」
**来源**：`song-demo` 主动对齐 + `flow-verifier` 独立验证

- `midi_rx.v`（CC123）与 `song_player.v`（停止）**已统一为这一种方言**
- ⛔ **`7'h7F` 广播码已废弃，不要在下游实现**
- **⇒ `top.v` 的消费者必须按 `off_note` 逐拍释放声部**
- 边界要注意：① 同一拍多个 off ② 声部已释放时再收 off
- 代价：129 clk = 2.58 µs，相对顶层去抖 2.621 ms 可忽略

### 2.3 `rxp` 引脚**不能带 `DRIVE=8`**
**来源**：`board-smoke` 实测 P&R 报错

> 官方引脚文件给 `rxp` 写了 `DRIVE=8`，但本器件/版本直接报
> **`ERROR (CT1108): Illegal port attribute value specified 'DRIVE = 8' on 'rxp'`**

**⇒ `.cst` 里 `txp` 可以带 `DRIVE=8`，`rxp` 不行。**（"官方文件也不能照抄"的又一实例）

## 3. 串口接入（契约由 `pc-link` 提供，已测）

```verilog
wire [7:0] uart_data; wire uart_valid;
uart_rx #(.CLK_HZ(50_000_000), .BAUD(115200)) u_uart (
    .clk(clk), .rst_n(rst_n), .rx(uart_rx_pin), .data(uart_data), .valid(uart_valid));

wire m_on_v, m_off_v; wire [6:0] m_on_note, m_on_vel, m_off_note;
midi_rx u_midi (.clk(clk), .rst_n(rst_n), .byte_data(uart_data), .byte_valid(uart_valid),
    .on_valid(m_on_v), .on_note(m_on_note), .on_vel(m_on_vel),
    .off_valid(m_off_v), .off_note(m_off_note));
```

**协议**：`115200 8N1`；`0x90 note vel` / `0x80 note vel` / `0xB0 0x7B 0x00`；**vel=0 视同 NoteOff**

⚠️ **哪个通道接 FPGA UART —— 待 `board-smoke` 实验结论**

⚠️ `midi_rx.v` **不支持 MIDI running status** —— 我们 GUI 每次发完整 3 字节，无影响；
但接真实 MIDI 键盘/DAW 会丢音（**需写进 README**）

## 8. 🔴🔴🔴 最关键：**事件消费纪律（`top.v` 必须做到）**

来源：`pc-link` 的分析（它**没有照抄我的判断**，而是自己算了一遍）。

### 上游**不需要** byte FIFO（算过了）
| 项 | 值 |
|---|---|
| 字节间隔 @115200 | **86.8 µs = 4340 clk** |
| `uart_rx` 打完 valid 回 IDLE | ~217 clk |
| `midi_rx` 消费一个字节 | **1 clk，无阻塞路径** |
| ⇒ 最坏阻塞 | **0 clk，余量 4340 倍** |

**而且**：`uart_rx` 在 FPGA 侧**只收不发**（没有 TX 通路）⇒ 探针那个"发送忙吞字节"的缺陷**不适用**。

### ⚠️ 真正的风险在下游 —— **加 byte FIFO 治错了端**
> `on_valid` / `off_valid` / `cc_valid` 都是 **1 拍脉冲、无握手**。
> **CC123 → 连续 128 拍 `off_valid`**（`song_player` 停止时 ~129 拍）= 2.56 µs。
> **若 `top.v` 的释放逻辑每拍消化不了 1 个脉冲，多出的脉冲被【静默丢弃】**
> ⇒ **症状：「按了全部停止，还有音在响」。**

**⇒ `top.v` 必须做到：**
1. **每拍消化 1 个事件**（用 pending 位图 / 计数器，不要用"忙等"或跨拍状态机）
2. 考虑把**广播语义改成电平/粘滞标志**（像 `reset_all` 那样），而不是 128 拍脉冲流

**验收判据**：CC123 到达后，**所有声部必须在 128 拍内归零**（用 `active` 位图或 `mix_out` 幅度验证）。

集成后逐条核，**F12 是最省事的总判据**：
> **综合报告里 BSRAM 应该是几十块（≈51/340）。若只有个位数而 LUT 暴涨 ⇒ 读路径没寄存、退化成分布式 RAM。**

| # | 检查项 |
|---|---|
| F1 | 用 `SDPB`（伪双口），不是 `SP` |
| **F2** | **读路径有寄存**（否则退化成分布式 RAM） |
| F3 | 无 Read-before-Write（138K 不支持） |
| F4 | 无同址读写 |
| F5 | 32 位不选真双口 `DP` |
| F6 | 读延迟已计入地址计算 |
| F7 | 状态头寸（上电清 BSRAM，否则反馈环 railed） |
| **F8** | 输入增益 `≤ 1 − g_max`（注意：不是 `1/(1−g)`） |

## 11. 🔴🔴 构建产物判据纪律（`board-smoke` 血的教训）

**它自己的构建脚本"假成功"⇒ 烧的是旧位流 ⇒ 白测一轮 ⇒ 跑去改设计（其实测的是旧逻辑）。**

根因：`build_uart.tcl` **只看 `.fs` 在不在**。而综合其实**报错失败**了：
```
ERROR (EX2000): Net 'hold_valid' is constantly driven from multiple places
Module 'uart_probe_top' remains a black box
```
**没有新 `.fs`，但上次残留的旧 `.fs` 还在** ⇒ 脚本报 "✅ bitstream"。

### ⇒ 全工程纪律（我的构建脚本必须照做）
```
① 构建【前】先删旧 .fs
② 要求 .fs 的 mtime >= 本次构建开始时间
③ 必须 grep 综合/布局报告里的 ERROR，不能只看文件存在
```
**⇒ 产物判据必须绑"这次构建"，绝不能只看文件存在。**

**同类教训（它同轮踩的）**：
- **`#(2200000000)` 超 32 位有符号 ⇒ 溢出成负数 ⇒ 延迟变 0**（`vlog-2597` 点破）
  ⇒ **TB 里长延时要用 `#2.2e9` 这种实数写法**
- **仿真没忠实复现真机时序**（13 ms 就注入，而真机是 PC 先听 5 s、心跳正在发送）
  ⇒ **仿真激励必须复现真机的时间上下文**，否则"仿真通过、板上失败"

## 12. ✅ 裁决：**上游不加 RX FIFO**（两方意见冲突，我采纳更严谨的一方）

| 主张 | 来源 | 依据 |
|---|---|---|
| **建议加 ≥1 深（推荐 16 深）FIFO** | `board-smoke` | 探针实测"发送忙会吞字节" |
| **不需要 FIFO** | `pc-link` | **算了实际时序余量**：字节间隔 86.8 µs = **4340 clk**；`midi_rx` 消费一个字节 **1 clk、无阻塞路径** ⇒ **最坏阻塞 0 clk，余量 4340 倍** |

**⇒ 采纳 `pc-link`**，理由：
1. 探针**收发共用一条 UART**（自己发送的 ~350 µs 窗口会吞字节）；
   而 `uart_rx.v` 在 FPGA 侧**只收不发**（没有 TX 通路）⇒ **"发送忙"不成立**
2. `pc-link` 给出的是**定量余量**（4340×），`board-smoke` 给的是**定性担忧**
3. **但采纳一条改进**（`board-smoke` 的建议）：**加"字节被丢弃"的可观测标志**（若真发生，能看见）

**⇒ 真正的风险是【下游事件消费】，不是上游字节**（见 §8）。**加 byte FIFO 会治错端。**

## 14. 🔴🔴 Verilog 静默陷阱：`signed [7:0]` 装不下 >127 的系数

**来源**：`song-demo` 效果器的一个真 bug（**18 PASS / 0 FAIL** 之前那一版是 14/4）。

```verilog
localparam signed [7:0] DAMP_NEW_C = 231;   // ⛔ 231 的 8 bit 有符号表示是 −25！
```
**一个符号性写错，同时造成两个看似无关的现象**：

| 后果 | 现象 |
|---|---|
| 阻尼级直流增益变成 `(25−25)/256 = 0` | **梳状反馈的直流通路被切断** ⇒ 状态几拍掉到 0 |
| 负系数进反馈环 ⇒ **变成振荡器** | 状态在饱和轨间翻转 ⇒ **全通被顶到 ±32767 并自持不衰减** ⇒ "混响尾巴不衰减" |

**⚠️ 现象指向全通，病根在梳状的阻尼系数。**
**它是靠"最小探针逐层读内部信号"（`tb_effects_probe.v`）才定位的 —— 光看输出永远查不出来。**

**⇒ 通用规则**：
> **凡系数可能 >127，绝不能声明成 `signed [7:0]`。Verilog 不会报错，只会静默变成负数。**

**正确写法**（其它模块一直如此，只有 `fx_comb` 被改坏）：
```verilog
localparam [7:0] DAMP_NEW_C = DAMP_NEW;                        // 无符号
wire signed [23:0] p_new = d_rd * $signed({1'b0, DAMP_NEW_C}); // 显式补 0 变正数
```

**同族**：本项目已多次栽在"符号性"上 —— `vmul[40:16]` 位选变无符号、
`{lfo_cos,1'b0}` 拼接变无符号、`uni_calc[18:0]` 位选越界。
**⇒ 每次用位选/拼接/窄位宽 localparam，都要问一句"符号还在吗、装得下吗"。**

## 15. 🔴 工具链坑：`Select-Object -First N` 会杀掉上游进程（**vsim 上后果更隐蔽**）

| 场景 | 后果 |
|---|---|
| 上游是 python | 证据文件只剩表头 ⇒ **得出反向的"没数据"结论** |
| **上游是 `vsim`** | **仿真被中途杀死、样本文件根本没生成** ⇒ 连续 3 次误判"没数据" |

**正确写法**：
```powershell
# ❌ ... | Tee-Object -FilePath $log | Select-Object -First 6
# ✅ ... | Tee-Object -FilePath $log | Out-Null ; Get-Content $log -Tail 20
```

**另一条**：**`vsim -g<param>=<value>` 对 Verilog 顶层 `parameter` 不可靠**
（实测 `-gNVOICES=16` 被解析成 **9326** ⇒ 实例化 9326 个声部 ⇒ 卡死）。
**⇒ 改参数请用 `vlog +define+NV=16` + RTL 里 `ifdef`。**
