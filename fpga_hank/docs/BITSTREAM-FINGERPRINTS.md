## 2. 🔴 三条必须一起读的"证据强度"说明

### 2.1 ⚠️ **MODE=2 的【原证据版】位流已丢失（已重建，但两者不是同一份文件）**
- `Lead` 的烧录记录说原份是"**16:30 构建的 `.fs`**"
- **但我在磁盘上找不到那个文件**：当时 `out/bitstream/` 里**没有 16:30 的产物**（实测该目录 7 个文件，时间为 14:30 / 15:04 / 15:18 / 15:22 / 16:46 / 16:50 / 17:49）
- **根因**：工程里的 `eda_proj/.../impl/pnr/fpga_hank.fs` **每次构建都被覆盖**，而**归档到 `out/bitstream/<模式名>.fs` 是【人工做的、没有脚本】**
  （实测：`tools/` 下**没有**任何自动归档脚本；`build.tcl` 只**报告**产物路径，不复制归档）
- **⇒ 后果**：`0x0000BB21` 这个指纹**指向一个已经丢失的产物** ⇒ **无法再烧回"产生 32 谱峰证据的那一份位流"**
- ✅ **补救（`Lead` 2026-10-05 18:37 已做）**：重建并归档为 **`MODE2_测试模式_32谱峰.fs`**（34,840,489 B / `68F7FFD22A9B1B18` / 18:37:18）
  - 资源：Logic 4 160 (3%) / Register 1 602 / BSRAM 1 / DSP 58；**时序 0 setup / 0 hold**
  - ⚠️ **它不是原证据版**：P&R 非确定性 + `User Code` 逐次随机（§2.3）⇒ **指纹不同是正常的**
  - ✅ **但 MODE=2 的 RTL 未变 ⇒ 功能等价**（可重新产出 32 谱峰）
- **⇒ 建议（已批准、待实现）**：**给 `build.tcl` 加一步自动归档**（构建后按 `MODE` 把 `.fs` 复制成 `out/bitstream/MODE<n>_<名字>_<时间戳>.fs`），**并在归档时把 `User Code` / 大小 / sha256 追加进本表**

### 2.2 ⚠️ **MODE=0 的 `User Code` 无法证明"绑到具体文件"**
- `Lead` 记录了 `0x0000C7B0`，也记录了它对应 `MODE0_演示模式_放歌.fs`（16:50:36）
- **但本项目没有"逐次烧录日志"**（`program.ps1` 不落盘 `User Code`）⇒ **无法从文件层面证明那次烧录烧的就是这一份**
- **⇒ 证据强度标为「凭证不足」**：**结论可信，但不可独立复核**
- **⇒ 建议**：让 `program.ps1` **把每次烧录的 `User Code` + 时间 + `.fs` 名 + sha256 追加到一个日志文件**（一行一条）

### 2.3 🔴 **`User Code` 不是设计标识，而是【逐次构建的随机量】**
- **实测**：`tools/gowin/program.ps1` L170-171 记着**早期**的 `0x0000A86D`（测试）/ `0x00005093`（演奏）；
  而 `Lead` 后来构建的**同类模式**得到的是 `0x0000BB21` / `0x0000C7B0` —— **同一个模式、不同次构建，值不同**
- **实测**：`tools/gowin/build.tcl`、`eda_proj/**/*.gprj`、`*.gprj.user` 里 **都没有 `user_code` 设置** ⇒ **是工具自动生成的**
- **⇒ 三条推论**：
  1. **重建同一份 RTL，会得到不同的 `User Code`** ⇒ **不能用它核对"重建结果是否等于历史产物"**
  2. **它唯一可靠的用途**：**烧录当场确认"我烧的就是我要烧的那个文件"**（配合大小/sha256）
  3. **⇒ 本表的 `User Code` 列只能标识【历史产物】，不能标识【设计】**
     判"是不是同一版设计"要**比对 RTL 源码**（见 README 附录 B：位流 SHA256 不能当修订标识）

## 3. 本表的维护方式（**给下一个人**）

```powershell
# 每次烧录后，追加一行（示例）
$fs = "fpga_hank\out\bitstream\MODE1_current.fs"   # = MODE1_H4校准_0违例.fs
$f  = Get-Item $fs
$h  = (Get-FileHash $fs -Algorithm SHA256).Hash.Substring(0,16)
"{0} | {1} | {2} | {3} | {4} | <User Code> | <烧录时间> | <真板结果> | <证据强度>" -f `
   "MODE=1", $f.Name, $f.Length, $f.LastWriteTime.ToString('yyyy-MM-dd HH:mm:ss'), $h
# 然后手动补 User Code / 烧录时间 / 真板结果 / 证据强度
```

**⚠️ 三条纪律**（来自本项目多次踩坑）：
1. **位流必须【归档】，否则指纹指向空气**（MODE=2 就是这么丢的）
2. **文件是否被 git 忽略必须双判据实测**：`git check-ignore --no-index` + `git ls-files -o --exclude-standard`
   （本表之所以放 `docs/` 就是因为 `out/` 被忽略）
3. **证据强度要标出来**：`日志实测` / `凭证不足` / `产物已丢失` —— **不要把"某人说"写成"已验证"**
