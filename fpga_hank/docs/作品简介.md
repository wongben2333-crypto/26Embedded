| 「32 谱峰测试模式」+「效果链」 | 同时点了赛题必备交付物与拓展②加分项 |

### 刻意没写的东西（以及为什么）

| 没写 | 原因 |
|---|---|
| **具体音色名（钢琴/电吉他/小提琴）** | ⚠️ **负责人明确指示：当前三种音色还原度尚未达标，点名等于给出可被当场证伪的承诺。** 泛化为"多音色"只是赛题名里的字，不额外担保。**后续任何人不要擅自把乐器名加回去。** |
| **具体传感器型号与形态对应** | 负责人要求泛化为"三种异构传感模态"；细节留技术文档 |
| 「六根弦」「具体几种音色」这类硬数字 | 代码里光电只实现 1 路；说数字反而有风险 |
| 作品名「芯弦和鸣」 | `_research/doc-draft/OUTLINE-v1.md` 里该项目名仍带问号，**未经确认** |
| 复音路数 | 位流做到 20 声部、目标 32，写哪个都可能被追问，**简介里只说"多声部并行"** |
| 「端到端延迟」 | 15.44 µs 只覆盖"控制事件→首样本"，**不含交互传感器自身响应**，故措辞收窄为"从控制事件到音频首样本" |

## 二·补 · 🎤 口头答辩备用说法（评委追问时用）

> ⚠️ **简介可以不写，但答辩躲不掉。** 赛题拓展②要求「≥2 种音色自由切换」，
> 评委大概率会问「你这几种音色分别是什么」「能弹一段吗」。**必须提前准备好说法。**

### 追问 1：「你这台乐器有哪几种音色？」

**❌ 不要说**：「钢琴、电吉他、小提琴」（一旦听感不像，当场失分）

**✅ 建议说**：
> 「合成内核是音色无关的，音色由波表与谐波权重表驱动，目前配了三套可实时切换的音色参数。
> 架构上支持任意多套，切换通过参数表索引完成，不重新配置 FPGA。
> 三套参数的具体听感还在调，最终会按评审意见收敛。」

**要点**：把话题从「**像不像**」引到「**架构支不支持**」—— 后者是硬事实，前者是主观听感。

### 追问 2：「听起来不像 XX 啊？」

**✅ 建议说**：
> 「当前是参数表初版，谐波权重和包络还偏简化。这一版的重点是证明
> **同一套硬件能在不重配 FPGA 的前提下实时切换音色族**，以及
> **每路声部都是独立相位累加器 + 频率控制字 + 包络**（可对照 RTL 逐行核验）。
> 音色逼真度是下一阶段的工作。」

**要点**：主动把评价维度从「音色逼真」挪到「**架构合规 + 可核验**」，并**主动认下差距**（比被指出好）。

### 追问 3：「能弹一段我听听吗？」

- 优先弹**你自己练熟的、短小的**片段（30 秒内），别弹难的
- **提前准备两套演示**：① 音色切换演示（同一旋律换音色，突出"切换"这一加分点）② 32 谱峰取证（突出规模）
- 如果现场听感不佳，**主动转向 32 谱峰测试模式** —— 那是纯客观证据，不依赖主观听感

### 三条底线

1. **绝不声称"这只和真钢琴一模一样"** —— 一旦被追问就崩
2. **绝不解释音色的技术细节**（谐波、共振峰…）除非评委明确问 —— 越解释越暴露
3. **所有细节都可以推给技术文档**：「这一块在文档第 X 节有完整的实现说明」
