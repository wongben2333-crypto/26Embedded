## A. Gowin 工具链（最烧时间的 6 条）

| # | 坑 | 后果 | 正确做法 |
|---|---|---|---|
| A1 | `-synthesis_tool` **只能写小写 `gowinsynthesis`** | `GowinSynthesis`/`GW_SH`/`Synplify` 报 `unknown synthesis tool` 并**中断整个脚本** | 用小写；⚠️ **官方 PDF SUG1220-2.1 的示例写的是大写 `GowinSynthesis`——照抄官方文档必踩**。该选项其实可以不设 |
| A2 | `gw_sh.exe` **不会切到 .tcl 所在目录**，`[pwd]` 是调用者 CWD | 相对路径全部算错，工程建到别处 | `set ROOT [file normalize [file dirname [info script]]]`。⚠️ `run close` 会把 CWD 弹回调用目录 |
| A3 | `.tcl` **不能带 UTF-8 BOM** | 第一条命令变成 `invalid command name "??oreach"` | 存无 BOM UTF-8 |
| A4 | `-verilog_std` 合法值**只有** `v1995`/`v2001`/`sysv2017` | `sysv2009` 报 `unknown verilog language value` 并中断 | 用合法值 |
| A5 | **`-device_version B` 会被静默接受** | 生成 B 硅片码流而 part 仍写 `C1/I0`，**零警告**，烧到 C 硅片直接错。只有 A/NA/X 才报错 | 按板上实际选 B/C |
| A6 | **缺 `.cst` 不报错** | I/O 自动摆放且默认不报位置 → **静默错脚** | 构建后核对 `impl/pnr/<name>.pin.html` 的引脚**确实是你要的** |

补充（同样实测）：
- **`.sdc` 不支持反斜杠续行** → `TA2000 near token '\'`，pnr 失败。每条约束写一行。
- **`TA1132`（时钟未创建）/ `PR1014`（时钟走通用布线）不在 `.rpt.txt` 里**，
  只在 console 与 `impl/pnr/<name>.log`。**检查告警必须看 log。**
- **`.fs` 字节数对该器件是常量（本设计恒为 34 840 489 B）** → **文件大小没有鉴别力**，
  不能用来判断"构建成功/内容已更新"。要核 `LastWriteTime` + 引脚报告 + 资源报告。
- **`open_project` 重跑会把产物名变成 `project.*`**，且旧 `<name>.fs` **不会被删**
  → CI 会拿**陈旧码流**当成功。每次构建前先删 `eda_proj/`。

## B. 交付级风险：Gowin 工程**不可移植**（实测换路径即报 EX5998）

- `.gprj` 的 `<FileList>` 全是**绝对路径**且含空格与用户名。
- 对照实验（全部本机实测）：
  1. `add_file` 传相对路径 → `.gprj` 里**仍写成绝对路径**（Gowin 强制规范化，**无法用相对路径规避**）
  2. 工程目录整体改名后再 `open_project; run syn` → ❌ **硬失败**
     `ERROR (EX5998) : Cannot open Verilog file '<旧绝对路径>'`
  3. 在**新位置重新跑 `build.tcl`** 再综合 → ✅ 成功
- ⇒ **交付物 = 源码 + 约束(`.cst`/`.sdc`) + `build.tcl` + 已生成的 `.fs`**；
  `eda_proj/`、`out/` 是**可丢弃产物**，不要当交付依赖。
- 好消息：这个失败是**响亮的**（Gowin 会打印缺失的绝对路径），不会静默用错文件。
- 工具：`scripts/check_portability.ps1`（`0`=没有 .gprj，`3`=有 .gprj+有 build.tcl=正常，
  `1`=有 .gprj 但找不到 build.tcl=**真风险**）。
- ⚠️ **换机复现的 3 个前提（均未验证）**：
  1. 目标机器需要**可用的 Gowin 授权**（本机是 STD license 到 2027-09-24；
     license 文件写的 `MODE=NODELOCK` **有误导性**，`HOST_ID` 与本机 WLAN MAC 完全一致
     → 实际是**绑本机网卡的节点锁**，换网卡/换机器需重新申请）
  2. 目标机器 Gowin 版本与器件库必须兼容 `build.tcl` 里写死的
     `GW5AST-LV138PG484AC1/I0` + `-device_version C`
  3. `.fs` 是"器件+版本"相关产物，只在**器件一致**时可直接烧录

## C. 验证方法论：反自欺（这一节最容易被跳过，但最省钱）

1. **判据本身必须先被验证。** `check_peaks.py --selftest` 的四项对照（本机实测 PASS）：

   | 对照 | 期望 | 实测 |
   |---|---|---|
   | 32 音 → int16 → I2S 打包/解包 | 逐样本无损 | True |
   | 32 音 → 逐 BCLK 位流 → 解码 → 分析 | 32/32 命中 | 32/32，0 杂散 |
   | **负对照**：只发 16 路、用 32 路判据 | 16 命中 + 16 未命中 | 16+16 ✓（判据有分辨力） |
   | **灵敏度对照**：人为硬限幅到 50% | 必须检出杂散 | 检出 **81** 个互调峰 ✓ |

   **没有负对照与灵敏度对照的"验证"，等于没验证。**

2. **工具缺失必须报 SKIPPED，不许报 PASS。** 本机实测 `verilator`/`iverilog`/`sby`/`verible`
   **全部未安装**（`Get-Command` 全空）→ `run_lint.ps1`/`run_formal.ps1` 返回 **exit 3 = SKIPPED**。
   所以现在**不能**声称"已通过 lint"或"已形式验证"。

3. **证据必须来自稳定快照。** 正在被写的文件（如 `out/tone_samples.txt`）读到"写了一半"
   的内容，会给出**看起来像数据的错误结论**（实测在同一个文件上连续两次得到互相矛盾的结论：
   先"离散度 6.83 dB"，再"match 13/32 + 19 杂散"）。
   ⇒ 先 `Copy-Item` 成快照再分析；`spectrum_report.py` 内置 sha256/mtime 前后比对，
   **退出码 5 = UNSTABLE = 结论无效**。
   ⇒ 同一纪律也适用于"读文件/搜索"本身：多人并行编辑时一次 `read`/`grep` 可能读到写入前的版本，
   **关键结论要复查一次再下**。

4. **退出码约定**：`0` PASS ｜ `4` 谱峰达标但增益不均 ｜ `1` FAIL ｜ `2` 输入错 ｜ **`5` UNSTABLE**。

## D. 采样率陷阱：`--fs` 漏传 → 32 个峰全部误判 FAIL

- 本项目音频 fs 由 `pt8211_tx.v` 决定：
  `fs = clk / (BCK_DIV × 帧长) = 50 MHz / (2 × 512) = ` **`48828.125 Hz`**，**不是 48000**。
- `fpga_hank/tools/verify/check_peaks.py` 的 `--fs` 默认值是 **48000**，
  而 `sim/tb/tb_spectrum.v` 头部注释的示例命令**漏了 `--fs`**。

  | 命令 | 结果 |
  |---|---|
  | `check_peaks.py --file ... --format samples --count 32` | **exit 1**，命中 0/32，200 Hz 读成 196.29 Hz（−3.71 Hz） |
  | 同上 + `--fs 48828.125` | **exit 0**，命中 32/32，最大误差 0.32 Hz |

- 误差 = 期望频率 × (1 − 48000/48828.125) ≈ **1.696%**。
- **纪律**：任何频谱/延迟计算前**先跑 `scripts/derive_fs.py`**。

## E. RTL 审查高频错（详见 `skills/verilog-review/SKILL.md`）

1. **同一寄存器被多次赋值**（最高频、最难查）。症状：寄存器卡死，或"每拍只前进半格"直至停滞，
   波形上像"设计不动了/复位没放开"。
   发现方法：对每个寄存器，数它在同一个 `always` 块里出现多少次 `<=`。
   **项目实例**：`pt8211_tx.v` 曾有 `new_ph <= ph+1` + 末尾无条件 `ph <= new_ph`，
   后者每拍执行而前者只在 tick 更新，构成串行延迟链，`ph` 每个 tick 只前进半格。
   ⇒ **不要为了"可读性"引入影子寄存器。**
2. **组合反馈/组合环**：综合报 combinational loop，或仿真振荡。
3. **不完整条件导致 latch**。
4. **位序/半帧边界类错误"看波形完全正常"** —— 唯一可靠验证是按 BCK 上升沿逐位解码 DIN
   再与期望样本比对（本项目 `sim/tb/tb_pt8211_final.v` 就是这么做的，抓出了 5 个"波形正常"的错误实现）。

## F. ModelSim

- **ModelSim 10.7 起 `-novopt` 已废弃**，加上会导致 `Error loading design`。
- **优化后读 DUT 内部寄存器可能得到与实际不符的值** → 调试优先做**纯黑盒验证**（只看输出端口），
  否则会被误导。
- `vlog` **没有 `-formal` 选项**（那是 Yosys/Verific 侧的）；ModelSim 下直接 `vlog -sv`
  即可编译 `assert`，加 `-formal` 会报 `vlog-1902`。

## G. PowerShell / 文件编码（会影响队友写的任何脚本）

1. **本机没有 PowerShell 7。** DSH 的 `pwsh` 工具实测是 **Windows PowerShell 5.1**
   （`5.1.26100.9444`，`PSEdition Desktop`）—— `Get-Command pwsh` **不存在**，不是"DSH 选了 5.1"。
   ⇒ **含中文的 `.ps1` 必须存成 UTF-8 with BOM**，无 BOM + 中文 ⇒ 中文必然乱码
   （实测输出 `涓枃娴嬭瘯`）；**是否进一步变成语法错误取决于具体字节序列**
   （实测 `Array index expression is missing` / `Missing closing '}'`）。
   ⚠️ **乱码比报错更危险：它 exit 0 照常跑完**，拿着错字符串继续工作，会**静默失配**。
2. **执行策略是 AllSigned**（`-List` 仅 `LocalMachine = AllSigned`，
   `$env:PSExecutionPolicyPreference` 为空 → DSH **不**替你注入 Bypass）。
   `powershell -File x.ps1` 与 `& x.ps1` 都失败（*is not digitally signed*，exit 1）。
   统一写法：`powershell -NoProfile -ExecutionPolicy Bypass -File <脚本>`
   （边界：ExecutionPolicy **只管脚本文件**，不管 `-Command`）。
3. **不要用 PowerShell `Set-Content -Encoding UTF8` 改带中文的 `.v`/`.tcl`**
   —— 它会加 BOM 并破坏中文编码，`vlog` 报
   `unexpected non-printable character with the hex value '0xef'`。
4. 非 `.ps1` 文件的编码体检（本 skill 实测）：
   `.py` UTF-8 **无 BOM 才正确**（加 BOM 反而不好）；`.do`/`.v` UTF-8 无 BOM + 中文注释
   **已验证可跑**；`.sby` 带中文注释的编码 ⚠️ **未验证**（本机无 sby）。
