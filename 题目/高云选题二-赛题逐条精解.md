## 1. 赛题结构总览（4 个部分）

> **读题顺序建议：先读「评分规则」，再读「基础要求」，最后读「拓展要求」** —— 因为评分规则决定了你该怎么设计。

### 设计要求（总纲 —— 一句话定义要做什么）
- 自研交互（电容触摸 / 光电 / 压力 / 手势任选）→ **≥2 个独立可控演奏维度**
- FPGA 硬件逻辑层搭**专属实时音频合成引擎**（波表 / 加法 / FM / 物理建模任选）
- **逐样本、逐声部**实时运算 → **I2S → DAC** 解码发声
- 目标：低延迟、高实时性、高表现力的**纯硬件**乐器

### 基础要求（3 项 —— 缺一不可）
1. **多维交互控制检测**：≥2 个独立可控维度，支持选音 / 触发 / 拨弦 / 力度感应
2. **FPGA 纯硬件实时音频合成**：全 HDL 实现，逐样本运算，控制到发声 **延迟 ≤10ms**
3. **合规实时发声与多复音**：**复音 ≥4**，ADSR 包络、实时变调、多声部混音，**严禁播放预录 PCM**

### 拓展要求（4 项 —— 加分项）
1. 超高规模并行合成引擎：**复音 ≥32** / 加法分量 ≥32 / 多物理建模单元
2. 多维表情控制与效果器：**≥3 维表情** + **≥2 音色** + 硬件混响 / 延迟 / 合唱
3. 极致低延迟与视听反馈：**≤5ms 且无抖动** + LED / 李萨如 / 频谱 / 波形
4. 智能联动与脱机拓展：脱机 LED 曲目指引 + 蓝牙 App 联动

### 核心评分规则（3 条 —— 决定你拿多少分，必须先读懂再动手）
1. **振荡器统计规则**：什么算"一个振荡器"（独立相位累加器 + 频率调控 + 包络控制，三者缺一不可）
2. **吞吐量指标**：**同时活跃可闻独立振荡器总数 × 实际音频输出采样率**（过采样不叠加加分）
3. **现场验证要求**：测试模式输出多路不同频率 → 频谱可观测对应数量独立谱峰 + RTL 代码佐证无预录

## 2. 基础要求逐条精解

### 基础 ①｜多维交互控制检测（≥2 个独立可控维度）

> **赛题原文**：自主设计演奏交互形态，基于各类传感器实现演奏动作精准采集，支持**选音、触发、拨弦、力度感应**等操作，具备**至少 2 个独立可控维度**，交互逻辑灵敏稳定，适配乐器演奏场景。

**逐句解读**
- **"自主设计演奏交互形态"** —— 不能直接买现成的电子琴键盘；要自己设计"琴键/演奏界面"（哪怕是一块铜箔电极、一排光电对管）
- **"基于各类传感器"** —— 官方点名 4 类候选：**电容触摸 / 光电感应 / 压力检测 / 无接触手势**
- **"至少 2 个独立可控维度"** —— 两个维度要**互相独立**。典型组合：
  - 维度 A = **音高选择**（按哪个键）
  - 维度 B = **力度/触发强度**（按多重 / 拨多快）
- **"选音、触发、拨弦、力度感应"** —— 至少要支持这些操作语义，不是"按一下就响"这么简单
- **"灵敏稳定"** —— 要消抖 + 滤波 + 防误触，现场演示不能乱响

**4 类传感器落地方案（按难度排序）**

| 方案 | 难度 | 实现要点 |
|---|---|---|
| **电容触摸** | ★★☆ | 电极片 + **约 1MΩ 上拉**；IO 先输出低电平放电 → 切高阻 → 电容经上拉充电 → 测量充到阈值的时间。手指靠近使电容增大、充电变慢。**有开源 IP 可直接参考**（`stnolting/captouch`，可把任意 FPGA IO 变电容键，自带校准与输出滤波）；也可直接用触摸 IC（AR101 / JL223B / TTP223）输出数字信号，最省事 |
| **光电感应** | ★★☆ | 红外光电对管 / 光敏电阻 + 比较器 → 数字触发。可做"**无接触琴键**"：手遮断光路即发声。响应快、无需接触；**需调制或滤波抗环境光干扰** |
| **压力检测** | ★★★ | FSR 压力传感器 + 分压 → 模拟电压。**FPGA 没有内置 ADC**，三条路：① 外部 ADC 芯片（如 ADS1115 via I2C）② RC 充放电时间测量（同电容触摸原理）③ ΣΔ 比较器法。用于**力度（velocity）**控制音量/音色亮度 |
| **无接触手势** | ★★★★ | 红外接近 / 超声波 / ToF 测距 → 手势判定。**演示最炫但最不稳**，建议作为第三维度而非主交互 |

**达标判据**：演示两个维度可独立改变（不同键 → 不同音高；按压力度 → 不同音量/音色）。

### 基础 ②｜FPGA 纯硬件实时音频合成（延迟 ≤10ms）

> **赛题原文**：完整音频生成通路**全部基于 FPGA HDL 硬件逻辑实现**，支持**逐样本实时音频运算**，可采用**波表采样、加法合成、FM 调频、物理建模**等任意方案；严格控制演奏延迟，实现**控制信号到音频输出总延迟 ≤10ms**，杜绝软件串行运算滞后问题。

**逐句解读**
- **"完整音频生成通路"** —— 从振荡器 → 包络 → 混音 → 效果 → I2S 输出，**全在 HDL 里**。软核（RISC-V）只能做参数配置/UI，**不能跑合成算法**
- **"逐样本实时音频运算"** —— 每个采样点都要现算，**不能"预先渲染一段再播"**。这是与"播放器"的本质区别
- **"杜绝软件串行运算滞后"** —— 明确禁止用 CPU 轮询 / 软核调度的方案
- **≤10ms 怎么算？** 全链路预算：传感器采样 + 消抖 + 键扫描 + 振荡器 + 包络 + 混音 + I2S 串行化。
  **关键**：I2S 缓冲别开大 —— 48kHz 下 1 个采样周期仅 20.8µs，但若用 512 样本 FIFO 就会引入 10.6ms 延迟，**直接超标**。

**4 种合成算法怎么选**

| 算法 | 说明 |
|---|---|
| **波表采样** Wavetable | **最推荐**：预存单周期波形 → 相位累加器查表。资源最省、音色可控、实现最直接。⚠️ 评分规则明确："**一个查表只算 1 个振荡器**" |
| **加法合成** Additive | 多个正弦分量叠加。音色最灵活（可精确复刻谐波结构），**但最耗资源**——每个分量都要独立振荡器。评分按"运算分量"计数，做 32 路即满足拓展① |
| **FM 调频** | 一个振荡器调制另一个的频率。少量算子（Operator）即可产生丰富谐波（Yamaha DX7 音色）。评分按"调制运算器"计数 |
| **物理建模** Physical Modeling | **Karplus-Strong**：激励（噪声脉冲）→ 延迟线（长度决定音高）→ 低通滤波（高频衰减）→ 反馈。拨弦音色最真实。评分按"并行弦/模态单元"计数 |

**延迟怎么测（答辩要用）**
- **GPIO 打标法**：触发瞬间拉高一个 IO，用示波器同时看"触发沿"与"音频输出起音点"，两点时间差 = 延迟
- 要报**最大值**与分位数，不能只报平均值

### 基础 ③｜合规实时发声与多复音能力（复音 ≥4 · 严禁预录）

> **赛题原文**：系统基础**复音数 ≥4**，支持四路及以上独立声部同时并发发声。严格遵循赛题合规要求：所有输出音频均由 FPGA 根据实时演奏指令**逐音、逐样本实时生成**，支持**单音实时变调、ADSR 包络调控、多声部实时混音**，**严禁直接播放预录 PCM 音频、预置推流及整段录音触发**，保障实时合成核心属性。

**逐句解读**
- **"复音数 ≥4"** —— 能同时发 4 个音（弹四音和弦），不是"能快速切换单音"
- **"单音实时变调"** —— 按住键的同时改变音高（滑音/颤音）。相位累加器的频率字必须可**运行时更新**
- **"ADSR 包络调控"** —— Attack 起音 / Decay 衰减 / Sustain 保持 / Release 释放。A/D/R 是**速率**，S 是**电平**；可用曲线 ROM（线性/指数/对数/S 曲线）提升自然度
- **"多声部实时混音"** —— 多路相加，必须做**溢出保护**
- 🔴 **红线：严禁播放预录 PCM / 预置推流 / 整段录音触发** —— 即不能塞 TF 卡播 wav。**现场会用频谱看独立谱峰 + 审查 RTL 代码**来验证

**架构要点：声部分配器（Voice Allocator）**
- 核心结构：**键扫描 → 声部分配器 → N 个并行振荡器 → 混音器 → I2S**
- 按下某键 → 分配一个空闲声部，把该键的频率字写入该声部
- 松开键 → 该声部进入 Release 阶段，释放完才回收
- **抢占策略**：声部不够时怎么办（最旧优先 / 最弱优先）—— 要写进报告

**两个必踩的坑**
1. 🔴 **混音溢出**：多路相加必溢出，会爆音。经验做法：**相加前先各自右移 1 位（除 2）**，或做饱和限幅
2. 🔴 **波表多端口访问**：BSRAM 端口有限，N 路同时读会冲突。社区实测：**强制把波表综合成 EBR 会导致复音异常**（EBR 串行访问）；分布式 ROM 可并行但耗 LUT。解法：复制多份波表到多个 BSRAM / 或内部过采样时分复用

## 3. 拓展要求逐条精解（加分项）

### 拓展 ①｜超高规模并行合成引擎

> **原文**：突破基础复音限制，实现**复音数 ≥32**，或**单音加法合成分量 ≥32 路**，或**多条并行物理建模运算单元**，最大化发挥 FPGA 并行计算优势，提升振荡器整体吞吐量。

**三条路径任选其一**
- **A**｜复音 ≥32：32 个独立振荡器同时发声（评分最直接）
- **B**｜单音加法分量 ≥32：一个音由 32 个正弦分量叠加
- **C**｜多条并行物理建模单元：多个 Karplus-Strong 弦并行

**资源可行性估算（Tang Nano 20K）**
- 板卡资源：**20,736 LUT / 15,552 FF / 828Kb BSRAM / 48 个 18×18 乘法器 / 2 PLL**
- 每路振荡器约：相位累加器 + 频率字 + 波表地址 + 包络 ≈ **150–200 LUT + 1 个 DSP**
- 32 路 ≈ **~6K LUT（29%）+ 32 DSP（67%）** → **可行**
- 波表 256 点 × 8~16bit ≈ 2~4Kb，BSRAM 有 828Kb → **复制多份毫无压力**
- 想更稳可选 **Mega 60K / 138K**（138K 有 138,240 LUT + 约 300 DSP）

### 拓展 ②｜多维表情控制与音频效果处理

> **原文**：搭建 **≥3 维演奏表情调控逻辑**，支持力度动态、滑音、颤音等演奏效果；支持 **≥2 种乐器音色自由切换**；在 FPGA 硬件内部实现**混响、延迟、合唱**等数字音频效果器，丰富演奏听觉层次。

**≥3 维表情**（在基础 2 维之上再加一维）：**力度** velocity（按压力度 → 音量/音色亮度）、**滑音** portamento（音高连续滑动）、**颤音** vibrato（LFO 调制音高）。

**硬件效果器实现路径（按难度）**

| 效果器 | 难度 | 实现要点 |
|---|---|---|
| **延迟** Delay | ★★☆ | BSRAM 循环缓冲 + 写指针 + 读指针（**read = write − delay**）+ 反馈 + 干湿比。开源参考最多，最容易落地 |
| **合唱** Chorus | ★★★ | 延迟线（约 20–30ms）+ **LFO 调制读指针**，产生多个轻微失谐的副本叠加 |
| **混响** Reverb | ★★★★ | Schroeder 结构：**4 个并联梳状滤波器（Comb）+ 2 个串联全通滤波器（Allpass）**，最复杂 |

⚠️ **坑**：BSRAM 是严格同步器件，必须用状态机做「读 → 等 1 周期 → 算 → 写」；**带异步复位会导致 BRAM 推断失败**。

### 拓展 ③｜极致低延迟与实时视听反馈

> **原文**：系统优化流水线架构，将演奏延迟压缩至 **≤5ms 且实现确定性无抖动延迟**；基于 FPGA 硬件逻辑实时生成可视化反馈，包含 **LED 演奏指引、李萨如图形、实时频谱、波形显示**等视听效果。

**"确定性无抖动"是关键**：不是平均值达标，而是**每次触发延迟都一样、最大值也 ≤5ms**。手段：**减少缓冲深度**、固定流水线级数、避免软核调度、效果链固定延迟。要报 **P50 / P95 / P99 / 最大值**，并说明测量起点终点。

**4 种可视化（必须由 FPGA 硬件逻辑生成）**
- **LED 演奏指引**：按曲谱节拍点亮 LED，辅助规范演奏
- **李萨如图形**：X = 左声道、Y = 右声道（或两个振荡器），逐点描迹 → 图形随音程变化，视觉极惊艳
- **实时频谱**：FFT（如 2048 点）→ 柱状图 ← **电赛信号题的强项，可直接复用**
- **波形显示**：采样缓存 → 屏幕描点

显示接口：Tang Nano 20K 有 **HDMI + 40Pins RGB LCD**；Primer 25K 有 3 个 PMOD。

### 拓展 ④｜智能联动与脱机拓展功能

> **原文**：实现**脱机演奏 LED 曲目指引**功能，辅助规范演奏节奏；可搭载**蓝牙模块与手机 App 联动**，支持**在线曲谱下载、演奏键位自定义、演奏录音回传**等拓展功能。

- **脱机 LED 曲目指引**：板载存曲谱 ROM（音符 + 时长），按节拍点亮 LED，**不需要 PC 参与**。"脱机"是重点——现场不能依赖电脑
- **蓝牙 + 手机 App**：需要蓝牙模块（HC-05 / BLE 串口透传）+ 自写 App

| 蓝牙功能 | 实现代价 |
|---|---|
| 在线曲谱下载 | App 下发曲谱数据 → FPGA 写入曲谱 RAM → LED 指引/自动演奏。**最易实现** |
| 键位自定义 | 下发"物理键 → 音高"映射表 → 存寄存器，运行时生效 |
| 演奏录音回传 | 需要**录音存储**（TF 卡 / PSRAM / 片上 BSRAM），再经蓝牙分包回传。**工作量最大** |

⚠️ 建议：时间不够时**果断放弃本项**，把精力投入拓展①（复音数）—— 那是评分公式里唯一的乘数项。

## 4. 核心评分规则（最重要，必须先读懂）

### 规则 ①｜振荡器统计规则 —— 什么才算"一个振荡器"

> **原文**：独立发声单元为包含**独立相位累加器、频率调控、包络控制**的完整振荡器；**单波表采样查表不计多谐波数量，仅计单个振荡器**；加法合成按**运算分量**统计、FM 按**调制运算器**统计、物理建模按**并行弦/模态单元**统计。

**三要素缺一不可** —— 要算"一个振荡器"，必须同时具备：
1. **独立相位累加器**（自己的相位寄存器）
2. **频率调控**（可独立改频率字）
3. **包络控制**（自己的 ADSR / 幅度包络）

- 🔴 **波表查表只算 1 个** —— 不能因为波表里"含 15 次谐波"就宣称 15 个振荡器。想凑数必须真的复制振荡器
- 加法合成 → 数**正弦运算分量**（32 个分量 = 32）
- FM → 数 **Operator / 调制运算器**
- 物理建模 → 数**并行弦 / 模态单元**

**策略含义**：**想拿高分 = 真实堆振荡器数量。** 用"一个振荡器输出复杂波形"是拿不到分的。最划算的路线是**波表 + 多振荡器**——每个振荡器都很便宜（约 1 DSP + 150 LUT），堆 32 路资源也可承受。写报告时要画清"振荡器实例框图"，明确标出每路的相位累加器 / 频率字 / 包络，**让评委一眼能数出来**。

### 规则 ②｜系统吞吐量指标 —— 你的最终得分公式

> **原文**：以「**同时活跃可闻独立振荡器总数 × 实际音频输出采样率**」为核心评分依据，**过采样不叠加加分**。

```
分数 ∝ 同时活跃可闻独立振荡器总数 × 实际音频输出采样率
```

- 过采样不叠加加分 ｜ "可闻" = 必须真的能听见 ｜ "实际输出采样率" = I2S 真正输出的采样率（如 48kHz），不是内部过采样的频率

**两条提升路径（相乘关系）**
- **路径 A：增加同时发声的振荡器数** —— 4 → 8 → 16 → **32**。这是主线，也是最可控的
- **路径 B：提高实际输出采样率** —— 48kHz → **96kHz**，分数直接翻倍。但注意采样率越高，每个采样点的运算时间预算越短（96kHz 下只有约 10.4µs/样本），需要更强的并行度
- 🔴 **钻不了空子**：内部做 10× 过采样（480kHz）不会让分数 ×10 —— 只认最终 I2S 输出采样率

**由此推导的行动优先级**
1. **复音数 ≥32**（拓展①）—— 分子翻 8 倍
2. **采样率提到 96kHz** —— 分子再翻倍
3. 保证"**可闻**" —— 32 路都要真的发声，不能有静默占位
4. 其余加分项（表情、效果器、可视化）—— 提升主观印象分，但不进公式

### 规则 ③｜现场验证要求 —— 必须交的"自证材料"

> **原文**：支持**测试模式下输出多路不同频率音频**，频谱可观测**对应数量独立谱峰**，同时可通过 **RTL 代码佐证纯硬件实时合成通路**，验证无预录音频播放行为。

**三条硬性动作**
1. **做"测试模式"** —— 一键（按键 / 串口命令）输出 N 路不同频率的音频。这是**必备交付物，不是可选项**
2. **频谱要能看到 N 个独立谱峰** —— 接声卡 / 示波器 FFT，屏幕上必须数得出对应数量的峰
3. **RTL 代码要经得起审查** —— 评委翻代码确认没有 PCM 播放逻辑（无 ROM 存音频样本、无 SD 卡读 wav）

**实操建议**
- 预留一个按键 / 串口命令进入测试模式，输出 **32 个均匀分布的频率**（如 200Hz 起、间隔 200Hz）
- 提前录好"**32 个谱峰**"的频谱视频/截图，放进作品视频与报告 —— 这是最有说服力的证据
- 在报告里加一节"**振荡器实例清单**"：列出 32 路各自的相位累加器位宽、频率字、包络模块名，方便评委对照代码数
- 代码命名规范：顶层信号/寄存器用小写、参数用大写（官方设计建议）

## 5. 适配板卡与音频通路

| 板卡 | 器件资源 | 音频通路（关键！） | 建议 |
|---|---|---|---|
| **Tang Nano 20K** | GW2AR-18：20,736 LUT / 15,552 FF / 828Kb BSRAM / 48 乘法器 / 2 PLL | **板载 MAX98357A I2S 功放**，可直接驱动喇叭；另有 HDMI + 40Pins RGB LCD + TF 卡槽 | 够用但资源偏紧，适合 32 复音 |
| **Tang Primer 25K** | GW5A-25：23,040 LUT / 23,040 FF / 1008Kb BSRAM / 28 乘法器 / 6 PLL | Dock 底板带 **PT8211 I2S DAC + 3.5mm 耳机口**（LPA4809 驱动）；3 个 PMOD | Sipeed 官方有 **PT8211 音频例程** |
| **Tang Mega 60K** | GW5AT-60：60K LUT / 2.6Mb BSRAM / PCIE 3.0 硬核 | 接口丰富，可外接音频模块 | 资源宽裕，推荐冲 32 复音 |
| **Tang Mega 138K** | GW5AST-138：138,240 LUT / 约 300 DSP / 8 路 6.6Gbps 收发器 | 接口最丰富，可做高采样率 + 大量可视化 | 资源最宽裕，上限最高 |

> **关键结论**：高云板卡**自带 I2S 音频通路**（Nano 20K 是 MAX98357A 功放，Primer 20K Dock 是 PT8211 DAC + 耳机口），而且 Sipeed 官方就提供 **PT8211 (Stereo Audio) 例程**——意味着"**先让板子出声**"这一步 1 天就能完成，不用自己设计模拟电路。这是本题相对其他赛题的一个巨大便利。

## 6. 要求 → 达标判据 对照总表

| 类别 | 要求 | 具体指标 | 达标判据 / 要提交的证据 |
|---|---|---|---|
| **基础** | 多维交互 | ≥2 个独立可控维度 | 演示两个维度可独立改变（如：不同键 → 不同音高；按压力度 → 不同音量/音色） |
| **基础** | 纯硬件合成 | 全 HDL、逐样本 | RTL 代码审查通过；无软核算合成算法的路径 |
| **基础** | 延迟 | 控制 → 发声 ≤10ms | 示波器 / 逻辑分析仪测"触发沿到音频起音点"，报最大值 |
| **基础** | 复音 | ≥4 路并发 | 同时按 4 键，频谱上可见 4 组独立谱峰 |
| **基础** | ADSR | 四段包络 | 示波器观察包络波形；参数可调 |
| **基础** | 实时变调 | 单音实时变调 | 按住键同时滑音 / 颤音，音高连续变化无断音 |
| **基础** | 混音 | 多声部实时混音 | 多音并发无削波、无爆音 |
| 🔴 **红线** | 无预录 | 严禁 PCM / 整段录音 | RTL 代码佐证（无音频样本 ROM）+ 频谱验证 + 测试模式 |
| **拓展** | ① 并行规模 | 复音 ≥32（或加法分量 ≥32 / 多物理建模单元） | 测试模式输出 32 路不同频率 → 频谱可数出 32 个独立谱峰 |
| **拓展** | ② 表情 | ≥3 维 | 力度 / 滑音 / 颤音逐项演示 |
| **拓展** | ② 音色 | ≥2 种可切换 | 运行中切换音色，不重启、不重新配置 FPGA |
| **拓展** | ② 效果器 | 混响 / 延迟 / 合唱 | 听感可辨 + 参数可实时调节（干湿比 / 反馈 / 衰减） |

| **拓展** | ③ 可视化 | LED / 李萨如 / 频谱 / 波形 | 现场展示，且由 FPGA 硬件逻辑生成（不能靠 PC） |
| **拓展** | ④ 脱机指引 | LED 曲目指引 | 脱机（不接电脑）演示曲目指引 |
| **拓展** | ④ 蓝牙 App | 曲谱下载 / 键位自定义 / 录音回传 | 手机 App 演示三项功能 |

## 附：优先级建议

| 优先级 | 事项 | 理由 |
|---|---|---|
| **P0** | 让板子出声 + 单音 DDS + I2S | 没有这一步，后面全是空中楼阁 |
| **P0** | 复音 4 → 32（拓展①） | **评分公式唯一的乘数项**，分子翻 8 倍 |
| **P0** | 测试模式 + 32 谱峰证据（规则③） | 必备交付物，也是最有说服力的加分材料 |
| **P1** | ADSR + 多音色 + 采样率 96kHz（规则②路径 B） | 分子再翻倍，且是基础要求 |
| **P1** | ≥2 维交互 + 力度（基础①） | 基础要求，必须做 |
| **P2** | 延迟 ≤5ms + 频谱可视化（拓展③） | 复用 FFT 强项，投入产出比高 |
| **P3** | 延迟/合唱效果器（拓展②） | 有开源参考，中等工作量 |
| **P4** | 混响（拓展②）、李萨如（拓展③） | 难度高或可选 |
| **P5** | 蓝牙 App（拓展④） | 工作量最大、加分最少，**时间不够果断砍掉** |
