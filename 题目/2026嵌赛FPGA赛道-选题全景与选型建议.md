## 4. 🥇 首选：安路 选题一 —— 基于 EG4S20 的 HDMI 多媒体播放系统

**最稳 · 生态最好 · 加分项清单化**

1. **门槛最低、边界最清晰**：全部是 FPGA 基本功（读卡 / BMP 解析 → SDRAM 帧缓存 → HDMI 时序 → I2S 音频），**没有 AI、DDR 控制器、多核 Linux、NPU 工具链**这些新手杀手——而这正是其他题目翻车的主因。
2. **官方把骨架给你了**：安路样例 **lab_ex_4 / lab_ex_5** 做的就是「图片 → SDRAM → HDMI 显示（含按键切图 / 轮播）」，另有网盘资料包 + 样例解析 + 官方 QQ 群，起点不是零。
3. **加分项被官方「清单化」**：字幕叠加、转场特效、自适应缩放、实时调参 OSD、音频可视化共 5 项，每项都不难；官方明说「完成 3 项以上且完成度高可得较高分」——这是 7 家题目里**最容易把「完成度」堆上去**的评分结构，而评委最看重的就是完成度。
4. **演示最强且不翻车**：HDMI 音视频 + 转场特效，评委一眼看懂。
5. **奖项池最大**：安路 2025 年一等奖 24 个（四家最多），板卡免押金借用，提交有效作品即归你。

**风险**：创新性偏弱、报名队数多。想冲一等必须把 5 项加分项做满 + 报告与视频包装到位。

## 5. 🥈 并列强推（看你们想要什么）

### 强推 1｜易灵思 赛题四 —— 实时图像边缘检测系统
*选它如果你们想要「最像教程、路径最清晰」*

**任务链**：DVP/MIPI 摄像头 → 行缓存 → 灰度化 → 中值滤波 → Sobel → HDMI/VGA 分屏显示

**为什么对初学者友好**
- **官方指南本身就是一份教程**：明确给出 Line Buffer 原理——2 个 FIFO/BRAM 缓存 2 行 + 列计数器，生成 3×3 滑动窗口。
- **Sobel 四级流水线**写得很细：部分和 → 完整 Gx/Gy → |Gx|+|Gy| → 阈值比较，优化后最高可跑 **220MHz**。
- 给了**资源优化技巧**：×2 用 `{data,1'b0}`、×3 用 `{data,1'b0}+data`；梯度用 `|Gx|+|Gy|` 代替 `sqrt(Gx²+Gy²)`，省 DSP 且效果足够。
- 给了**分模块调试顺序**：① 显示彩条 → ② 摄像头直通 → ③ 加灰度 → ④ 加 Sobel → ⑤ 加高阶项。这是避免"最后一刻才发现问题"的关键。
- 给了**周期预估**：基础要求 3–4 周（含调试）；加中值滤波 + 阈值调节 5–6 周。
- 高阶项里官方点名「**阈值实时调节是性价比最高的加分项**」——只需在比较前加一个可配置寄存器 + 按键增减，现场演示能直观展示边缘灵敏度变化。

**风险与拿奖画像**
- ⚠️ Efinity 工具链冷门、Ti60F225 生态小，IP/时序出问题时可查资料少。**建议尽早把 MIPI CSI-2 RX + DDR 控制器 + HDMI 三个官方 IP 跑通**，再谈算法。
- 其他加分项：中值滤波（9 像素排序网络，5 周期输出中值）、DDR 帧缓存（回放/帧冻结/多帧对比）、Canny、彩色边缘叠加、简易形状识别。
- **二等画像**：稳定完成基础要求 + 画面无丢帧错位。
- **一等画像**：基础 + 中值滤波 + 阈值调节 + Canny/彩色叠加，且能报出流水线频率与资源占用。

### 强推 2｜高云 选题二 —— 实时多音色合成电子乐器引擎
*选它如果你们想发挥电赛信号处理背景 + 做差异化*

**任务链**：自研交互（电容触摸/光电/压力/手势，≥2 个独立可控维度）→ FPGA 内纯硬件音频合成（波表采样/加法合成/FM 调频/物理建模）→ I2S → DAC 发声

**为什么值得选**
- **纯 DSP/信号处理，正好对口电赛信号题背景**。
- **没有摄像头/DDR/AI 的复杂度**，全链路自包含在 HDL 里。
- 评分**客观可算**：官方明确以「**同时活跃可闻独立振荡器总数 × 实际音频输出采样率**」为核心评分依据，过采样不叠加加分。
- 音频题**做的人少**，差异化明显，不易同质化。
- 现场能真的"弹"出声音，**互动演示效果极佳**；官方还鼓励录「抖音/B站风格」短视频作为附加材料。
- 合规红线清晰：所有音频必须逐音逐样本实时生成，**严禁直接播放预录 PCM/整段录音触发**——现场可用频谱仪验证独立谱峰数量。

**风险与拿奖画像**
- 硬指标：基础复音数 **≥4**、控制到发声总延迟 **≤10ms**、支持 ADSR 包络/单音实时变调/多声部实时混音。
- 拓展：复音 **≥32**（或加法合成 ≥32 路）、**≥3 维**表情控制（力度/滑音/颤音）、≥2 种音色切换、硬件混响·延迟·合唱、延迟 ≤5ms、LED/李萨如/频谱/波形可视化。
- ⚠️ 音质与复音数要真功夫（多路振荡器 + 混音 + 包络需精细的流水线与资源管理）；交互传感器需自研，结构/触感设计要花时间。
- **二等画像**：4 复音 + 多音色 + 无杂音，能连续稳定发声。
- **一等画像**：32 复音 + 硬件效果器 + 实时可视化 + 现场频谱验证。

### 强推 3｜中科亿海微 选题一 —— 基于以太网 MAC 实现 AFDX
*选它如果你们想吃「新赛道信息差」，且想规避硬件翻车*

**任务**：基于以太网 MAC 控制器，用 FPGA 实现 ARINC 664 Part 7 端系统——UDP/IP 协议处理、缓冲区管理、发送调度与接收管理、媒体接入控制，并支持 SNMP 网络管理、615A 数据加卸载、RTC 时钟同步。

**为什么赔率高**
- **完全不需要硬件平台**（官方原文：「本赛题全部通过 eLinx 软件进行编译及仿真，无需硬件平台」）——直接消除「板级调试翻车」这个最大的失败模式。
- 评分 **100% 落在代码/文档/仿真**上，全部可控：代码及仿真环境 **40%** + 设计文档 **20%** + 测试报告 **20%** + 技术指标 **20%**。
- **中科亿海微是 2026 年首次进入 FPGA 赛道的厂商**，参赛队预计极少。
- 题目偏「航电总线」（ARINC 664），**绝大多数本科生不会选**，竞争密度极低。
- 对口 RTL 设计背景，是标准的数字系统设计题。

**风险与拿奖画像**
- 技术指标：100 Mbps；帧格式 IEEE 802.3 + ARINC 664 扩展（VLID + 序列号 1–255，有效载荷 ≤1471B，总帧长 ≤1518B）。
- 性能要求：端到端时延 **<1–2ms**、抖动 ≤ 几十微秒；支持最多 **128 个发送 VL、4096 个接收 VL**。
- ⚠️ **风险 1**：资料最少（新厂商 + 航电标准，中文教程稀缺）。
- ⚠️ **风险 2**：演示感弱（纯仿真，没有实物画面），答辩要靠仿真波形与量化数据说话。
- ⚠️ **风险 3**：协议栈工作量大——UDP/IP + 缓冲管理 + 发送调度 + SNMP + 615A + RTC 共 6 件事。
- **建议**：先把 MAC + UDP/IP + VL 调度跑通并给出仿真报告，再逐项补 SNMP/615A/RTC。

> **附**：如果你们的集创赛背景偏 **EDA/综合**，可考虑中科亿海微 **选题二 PMUX 结构优化**（Yosys 自定义 Tcl 插件 + 形式等价验证 + 面积缩减 ≥10%）。竞争更小、评分更客观（功能 10 + 优化 40 + 效率 30 + 文档 5 + 答辩 15），但它是「研究型」题目，**面积优化指标是硬门槛**，风险高于 AFDX。

## 6. ⚠️ 不建议初学者碰（附原因）

### A 类｜复合门槛型 · 多芯片异构 + AI 部署 + Linux/工具链，2 个月做不完整闭环

1. **AMD 赛道一：RTL/HLS 本地智能体设计** — *大模型工程 + 硬件设计 双料难题*
   要在 **32GB 单卡**内本地部署开源大模型（32B 级需 4-bit 量化才装得下，FP16 约需 64GB 装不下），再自研 Agent + 技能包，在**断网沙箱容器**里跑 VerilogEval/HLS-Eval 并比 pass@1/pass@5。评分中 **40% 看「相对同模型裸跑基线的增益」**——没有模型调优经验基本无从下手。

2. **AMD 赛道二：具身智能** — *证据链要求极高*
   硬性要求 AMD Ryzen AI PC（ROCm 7.14+）+ FPGA/Zynq 双端闭环，并报告 **5 类核心指标**（闭环成功率、端到端延迟 P50/P95/P99、AI 效果、FPGA 量化贡献、双端通信性能）+ 至少 2 项场景指标，**每项都要可复测证据**（原始日志、示波器/逻辑分析仪截图）。工程量与证据链要求远超本科团队常规能力。

3. **复旦微：开放选题（FPAI 悟净）** — *双工具链 + 双门槛*
   硬性「**≥1 个 AI 算法部署 + ≥1 项 FPGA 开发 + 端到端闭环**」，需同时掌握国产 NPU 工具链 **Icraft**（模型转换/量化/仿真/上板）与 FPGA 工具 **Procise**。工具链新、资料少，两个工具都踩坑的概率很高；且是新厂商，遇到问题可求助的人更少。

4. **安路 选题三：图像采集压缩 + 智能预处理加速（PH1A90 + RK3576）** — *6 项硬性任务缺一不可*
   MIPI CSI IP 核 → ≥3 种硬件预处理 → JPEG/LZ77 硬件压缩 → MIPI·PCIE 高速通道 → RK3576 NPU 推理 → 量化测试报告。等于「**FPGA 图像 + 硬件压缩算法 + 异构高速接口 + NPU 部署**」四合一，任何一环卡住都无法交付。

5. **安路 选题四：飞龙 SoC 智能工业系统** — *FPGA + Linux + NPU 三修*
   6 项硬性任务：PL 端工业级硬实时（多轴 PWM / 多通道同步采集 / 工业总线时序三选一）、PS 端 Linux + 人机界面、AXI 双向高速交互、内置 NPU 工况识别、CAN/RS485、完整量化报告。要求同时具备 FPGA 逻辑设计与嵌入式 Linux 驱动/应用开发能力。

6. **紫光同创 选题三：ADAS 高级辅助驾驶** — *现场用 U 盘数据集当场评*
   FPGA + ARM（≤RK3568）软硬协同，识别斑马线/行人/路障，模拟变道/超速/碰撞提醒；高阶要 4 路视频并行采集 + 夜间与复杂路口场景 + MCU 端轻量 AI 模型 + 自主路径规划。决赛**用 U 盘提供十字路口/变道/红绿灯测试数据集当场评测**，场景不可控，翻车即出局。

7. **高云 选题三：具身智能机器人感知与自主控制** — *全栈 + 现场不确定性大*
   基础要求已含多传感器（摄像头 + IMU）+ 运动控制（编码器闭环）+ 避障（超声波/TOF/激光）+ 自主导航（起终点 + 路径点）；拓展还要 RK3588 上做视觉识别 + 语义导航（如"找到红色水瓶并移动到附近"）。机器人是「机械 + 电控 + 算法 + 感知」全栈，调试周期长、现场演示不确定性大。

### B 类｜算法硬核型 · 要自研加速器/复杂算法，超出初学者射程

8. **易灵思 赛题一：AI 实时绘画（风格化视频渲染）** — *神经网络硬件加速课题*
   要自己设计风格迁移网络（简化版 CycleGAN / Fast Neural Style / 自研微型 CNN）的硬件加速器，**卷积层、ReLU、批归一化/实例归一化全部硬件化**，还要做行流水线优化（避免整帧输入整帧输出）与 DDR 访问削减。这是通常需要研究生级投入的课题。

9. **易灵思 赛题二：2D 图形渲染加速引擎（BitBlt）** — *门槛稍低但高阶很重*
   基础（块拷贝/纯色填充/VGA·HDMI 时序/双缓冲）尚可，但高阶项——**硬件 Alpha 混合、Color Keying、跑到 60fps 的弹幕级 Sprite 数量**——对总线突发传输、FIFO 深度、带宽预算要求很高；还要在 FPGA 内跑 RISC-V 软核 + 自定义外设，开发链偏重。

10. **易灵思 赛题三：多模态 AI 智能终端** — *传感器多 + 标定复杂*
    视觉（720p@30fps）+ MLX90640 红外热成像（要自己读 EEPROM 校准参数，做环境温度/增益/偏置/发射率补偿）+ SHT30 + TinyML 推理 + 多模态融合决策 + 时间戳对齐 + 至少 2 项拓展。本质是「**多模态融合**」难题，标定与对齐工作量巨大。

11. **紫光同创 选题二：任意角度畸变矫正** — *精度指标很硬*
    二阶径向/切向畸变坐标映射 + 双线性插值重采样 + 1080P@30/60fps 实时；高阶还要结合 IMU 做动态仿射变换与自适应 Gamma/直方图均衡。评分看 **MTF50/SFR 空间频率响应与直线度误差**，精度指标硬；且需自行准备标定板 + OpenCV 标定流程。

### C 类｜传统热门型 · 能做出来，但很难赢过强队

12. **紫光同创 选题一：RISC-V RV32I CPU 设计** — *对口集创赛，但冲一等性价比低*
    对集创赛背景**最对口**，但它是每年的"兵家必争之地"，一等奖基本被成电/西电/东南等强校包揽。评分是 **CoreMark 跑分**（执行效率 CoreMark/MHz、最高主频、CoreMark/LUTs 资源效率）**纯客观性能竞赛**，还要求用 ILA 抓波形分析流水线效率。初学队伍跑通 CoreMark 拿二/三等可控，但冲一等很难。**结论：可作为「保底」选项，而非「冲奖」选项。**

## 7. 拿奖执行要点

> **比赛比的是「完成度」，不是「参数极致」**

1. **做不出来就跳过。** 几乎没有哪年的题目能全部指标满分，保留半成品进度，报告与演示都能拿「辛苦分」。
2. **初赛只保证进线下，最终评分在线下。** 提交后到决赛还有半个月，继续打磨，别提交完就摆烂。
3. **必须过 Verilog 能力测评。** 决赛现场考核，不合格直接降档；提前刷题（GitHub 有公开的往届测评题库）。
4. **准备第二套方案与备份硬件。** 往年「只有一套方案、现场调不出来」而丢奖的大有人在，别抱侥幸。
5. **分工**：FPGA 1–2 人（拆接口/算法），硬件或上位机 1 人，剩下的人写报告 + 拍视频 + 整理资料。别硬凑 3 人做同一个工程。
6. **从第一天就留痕。** 阶段性进展就录视频、存源码；写报告不用从零开始，工程崩了还能拿旧素材顶上。
7. **答辩准备**：限时讲稿（掐点就停，讲不完很吃亏）、「为什么没达到某参数」的话术、方便展示的物料（海报 / 第二块板子 / 现场测不出的素材）。
8. **多混官方 QQ 群。** 共性坑一定有人问过，别自己到处百度；官方宣讲会会解读评分标准与往届获奖作品。
