## 0. 一页读懂

- **为什么不直接写 Verilog**：赛题唯一进入评分公式的是「**同时活跃可闻独立振荡器总数 × 实际音频输出采样率**」。分子要堆到 32，分母受 GW5AST-138 的 298 个 DSP / 138K LUT 约束。**32 路怎么映射到位宽、波表要不要抗混叠、混音怎么不溢出**——这些在 RTL 里改一版要几小时，在 Python 里改一行只要一秒。于是把 RTL 的试错全部前移到软件。
- **我们做了什么**：一套与 RTL 结构一一对应的 **Python 黄金参考模型（16 个模块）** + 一键集成脚本，产出音频、频谱、位宽曲线、资源账、延迟预算、以及**可直接被 Verilog 读取的参数头文件与波表数据**。
- **最重要的三条结论**：
  1. **32 复音在 138K 上资源极充裕**：LUT 5.9% / DSP 10.7% / BSRAM 0.3%。
  2. **延迟 0.354 ms（48k）/ 0.177 ms（96k）**，远低于 ≤5 ms；唯一能撑爆预算的是 I2S FIFO 深度，必须保持浅。
  3. **测试模式 32 路独立谱峰已跑通**（200–6400 Hz，间隔 200 Hz，检测 32/32）——这是评分规则③要求的现场证据，已提前拿到"预演图"。

## 1. 背景：为什么先做算法模拟

### 1.1 评分公式决定设计方向

| 规则 | 原文要点 | 对我们的含义 |
|---|---|---|
| ① 振荡器统计 | 一个"振荡器"必须含**独立相位累加器 + 频率调控 + 包络控制** | 想拿分必须**真实堆振荡器数量**，不能靠"一个复杂波形"充数 |
| ② 吞吐量指标 | **活跃独立振荡器总数 × 实际输出采样率**（过采样不叠加） | 两条提分路径：**复音 4→32** 与 **采样率 48k→96k**，相乘 |
| ③ 现场验证 | 测试模式输出多路不同频率 → 频谱可见**对应数量独立谱峰** + RTL 佐证无预录 | 必须做"测试模式"，并准备 32 谱峰证据 |

### 1.2 必须在写 RTL 前定死的三件事

1. **算法结构**：波表 / 加法 / FM / 物理建模怎么选、复音怎么分配、效果链怎么排。
2. **定点位宽**：相位、波表、包络、乘法器、混音累加每一级的最小可行位宽——直接决定 LUT/DSP 用量。
3. **资源与延迟账**：32 路到底占多少资源、全链路延迟能不能进 5 ms。

这三件事用软件定死，RTL 才能一次成型、少走弯路。

| 决策 | 选择 | 理由 |
|---|---|---|
| 主线合成算法 | **波表为主 + 加法冲 32** | 波表资源最省、音色可控；加法合成 32 分量满足拓展①路径B，且贴合"按运算分量计数"的评分口径 |

## 5. 关键设计决策与坑

### 5.1 带限波表 + mipmap 抗混叠
- 直接查"理想锯齿表"，高音会因谐波超过奈奎斯特而混叠。
- 方案：每个波形生成 **8 级带限表**，第 k 级只保留 `max(1, 512>>k)` 次谐波；演奏时按基频选层（`select_mip`）。
- 实测：440 Hz 落在 L4；每级 DC 严格为 0；`wavetable_saw.mem` 已导出。

### 5.2 定点位宽 —— 最省资源的一步
- 用 `fixedpoint.sweep_requant` 扫描 4→20 bit，SNR 呈现标准 **~6.02 dB/bit** 斜率。
- 结论：**16-bit 足够**（SNR ≈ 98 dB），再高的位宽收益递减却增加 LUT/DSP 压力。

### 5.3 混音余量 —— 防爆音
- 32 路满幅相加最坏可达 +30 dB。做法：**每声部先右移 `voice_gain_shift=5` 位（÷32）再相加**，最后饱和限幅。
- 实测：最坏情况总线电平 ≈ 0.003 dBFS（刚好贴满不过冲），32 路实际混音峰值 -11.3 dBFS。

### 5.4 力度（velocity）只应用一次
- 契约中 `Voice.step = osc × env × velocity`，而 `ADSREnv.note_on(velocity)` 也会设峰值——**若两处都乘会变成 velocity²**。
- 决策：**Envelope 在 Voice 内保持归一化（peak=1.0），velocity 只在 Voice 输出乘一次**，与 RTL 的"三个独立乘法器"结构一致。此决策写进了模块 docstring。

### 5.5 I2S FIFO 必须浅 —— 延迟的唯一杀手
- 48 kHz 下 1 个样本 = 20.8 µs。深度 512 的 FIFO 单独就引入 **10.7 ms**，直接超标。
- 决策：`i2s_fifo_depth = 4`。延迟预算脚本内置"深 FIFO 反事实"对比，佐证这一点。

### 5.6 波表多端口访问（社区踩坑）
- 多声部同时读同一张 BSRAM 波表会串行冲突。缓解手段：**复制多份波表**（16 KB 占用对 6120 Kb 可忽略）或**内部时分复用**（TDM）。
- 资源估算中已把波表按"共享 ROM、全部 mip 层驻留"计（仅 16 KB）。

### 6.3 数据流 —— 一个音怎么被算出来（算法全流程）

以「按下 MIDI 69（A4=440Hz），力度 0.8」为例：

```
① note_on(69, 0.8)
   └─ allocator 找一个空闲声部（没有则按 oldest / weakest 抢占）
   └─ voice.note_on(freq=440, vel=0.8)
        ├─ DDSOsc.set_freq(440)  → 频率字 FWORD = round(440/48000 × 2³²)
        └─ ADSREnv.note_on(1.0)  → 进入 ATTACK

② allocator.render(n) 每渲染 n 个样本：
   for 每个活跃声部 v:
       v.step(n) =  osc.step(n)  ×  env.step(n)  ×  velocity
                     │                │              │
             DDS: 相位累加→查表   ADSR 状态机    力度增益
                  →线性插值        ATTACK→DECAY
                                   →SUSTAIN→RELEASE
   mixer.mix_sum(signals, shift=5, saturate=True)
        └─ 各声部相加 → 整体 ×2⁻⁵（余量）→ 限幅到 [-1,1]

③ （可选）effects.delay / chorus / reverb 叠加效果
④ render.write_wav(...) → 16-bit PCM 单声道 WAV
```

**四个关键约定**（都对应 RTL 结构，便于日后逐个对齐）：

1. `Voice.step = osc × env × velocity` —— **力度只乘一次**（env 在 Voice 内保持归一化 [0,1]）。
2. **混音先移位再相加**（`shift=5`）：32 路最坏情况刚好贴满 0 dBFS，靠饱和兜底。
3. 波表查表走 `freq_word → 相位序列 → 插值`，`dds.phase_sequence` 返回**步进前**的相位，方便 RTL 逐周期复现。
4. 高音通过 `select_mip` 自动选低谐波段，避免混叠。

> 单声部基准（假设，已写进源码注释）：约 **200 LUT + 124 FF + 1 DSP**。结论：**32 复音余量充足，最坏资源占用仅 DSP 的 10.7%。**

### 7.5 延迟预算

| 阶段 | 样本数 | 48k (ms) | 96k (ms) |
|---|---|---|---|
| 输入扫描/消抖 | 3 | 0.062 | 0.031 |
| 合成流水线 | 5 | 0.104 | 0.052 |
| 波表读取 | 1 | 0.021 | 0.010 |
| 包络更新 | 1 | 0.021 | 0.010 |
| 混音 | 2 | 0.042 | 0.021 |
| **I2S FIFO** | **4** | **0.083** | **0.042** |
| DAC/串行化 | 1 | 0.021 | 0.010 |
| **合计** | **17** | **0.354** | **0.177** |

> 反事实：若 I2S FIFO 深度取 256，则 48k 下为 **5.33 ms**——单独就撑爆 5 ms 预算。**结论：FIFO 必须浅。**

## 8. 对 RTL 实现的直接指导

1. **参数以 `out\synth_params.vh` 为准**：位宽、深度、采样率、器件资源全部宏定义，Verilog 直接 `` `include "synth_params.vh" ``，杜绝手算频率字。
2. **波表数据用 `out\wavetables\*.mem`**：`$readmemh` 直接载入；四波形（sine/saw/square/triangle）各 8 级 mipmap。
3. **振荡器实例清单要"可数"**：报告与代码需清晰标出每路的**相位累加器 / 频率字寄存器 / 包络模块**（评分规则①三要素），方便评委对照 RTL 数出 32 路。
4. **测试模式必备**：一键进入、输出 32 路等间隔频率；用 `out\testmode_32peaks.png` 作为预期效果基准。
5. **延迟测量方法**：GPIO 打标法——触发瞬间拉高一个 IO，示波器看"触发沿→音频起音点"，报 **P50/P95/P99/最大值**。
6. **合规自证**：RTL 中不得存在音频样本 ROM / SD 卡播 wav 逻辑；代码命名遵循官方建议（信号小写、参数大写）。

## 10. 假设、边界与风险

1. **资源/延迟为"单位点估算"**：单声部 200 LUT + 1 DSP 等均为工程假设（已注释在源码），真实数字须待 RTL 综合后对齐；但量级与余量足以支撑方案决策。
2. **48k 与 96k 均已覆盖**：96k 下 32 声部核心占空比约 100%（脚本给"50% 余量"下为 16 声部）；若要 96k 跑 32 声部，需更激进的流水线/TDM 优化。
3. **效果器/混响为纯算法模型**：未含定点/延迟线资源细算，落地时需按 BSRAM 重新评估。
4. **未涉及交互传感器**：自研琴键（电容/光电/压力）属硬件工作，不在本模型范围。
